这本书的数从哪来

没有引用任何论文里的指标。干净语音是用源-滤波模型合成的：基频曲线、共振峰轨迹、每个音段的起止都是已知真值，所以"增强丢了什么"才有客观答案。神经网络那几节是真训的——纯 numpy、手写反传、严格因果，在 6,696 帧上训练，测试语音训练时没见过。

代价要说清楚：这些都不是真录音，绝对数值不能直接和 DNS 挑战赛上的结果比。可比的是形状、量级和趋势——而这本书要讲的恰好是形状。

一个贯穿全书的量，和它的理论零点

要说"假设失效了多少"，需要一个能量的东西。全书用的是残差的帧间起伏：同一个频点上，残留噪声的功率在帧与帧之间跳得有多厉害（dB）。

它有一个漂亮的性质：平稳高斯噪声的周期图服从 χ²₂，取对数之后的标准差恒为 10/ln10·π/√6 = 5.57 dB，与处理无关。所以这个数是"完全没有音乐噪声"的下限，读数高出多少，就是多出来的起伏。

实测不处理的带噪信号：5.55 dB。和理论值差 0.017 dB——这也顺带验证了整套仿真没写错。

书里有四处我猜错了

判决引导只是"平滑"、短窗系统可以不管相位、时频分辨率对非平稳噪声更值钱、拐点在直觉的位置——这四个假说都被我自己的对照实验否掉了，我把它们连同否掉它们的实验一起留在正文里（08、11、20 节）。

留着是因为在这个方向上，错误的归因比错误的结论更常见：一个参数确实带来了提升，但提升的来源和你以为的不是一回事，于是换个场景就失效了。

01自由度为零入门

一句话版

多通道能把目标和干扰在空间上分开，单通道只能在时频上分。而时频上分不开的时候，就只能靠假设。

把问题写下来，只有一行：

① 观测模型与唯一的输出

y(t)=s(t)+v(t) STFT ​Yk,l​=Sk,l​+Vk,l​整本书只有这一个输出：每个时频点上的一个实数增益​S^k,l​=Gk,l​Yk,l​​​

注意 G 是一个实数——它只改幅度，相位原样放回去。这个选择在 1979 年是出于计算量，在 2020 年之后才被真正挑战（11、12 节）。但整个经典体系都建立在它上面。

为什么"逐时频点压增益"是唯一能做的事

多通道系统可以用一个线性滤波器把干扰抵消掉：因为不同方向的声音在麦克风之间有不同的相位差，这个差异是确定性的、可测的。

单通道没有这个信息。你手上只有一路时频谱，唯一能做的是判断每个格子里"语音成分多还是噪声成分多"，然后按比例衰减。这不是某种实现上的偷懒，它是信息量决定的。

"单通道降噪"这个说法掩盖了一件事

它听起来像"多通道的简化版"。实际上它是另一类问题：多通道做的是分离，单通道做的是估计——在每个格子里，从一个被污染的观测里猜出干净的那部分。

后果是：多通道的失真可以做到很小（理想情况下为零），而单通道必然在语音失真和残留噪声之间做取舍。这个取舍是下一节要量的东西。

那它还有什么用

三件事：

① 绝大多数设备只有一个麦克风的可用通道——手机通话、有线耳机、老式会议设备、存量录音。

② 多通道系统的后置滤波本质上就是单通道增强。波束形成之后残留的扩散噪声，只能用这一套方法处理。

③ 它是理解整个语音增强问题的最短路径：所有的概念——先验信噪比、语音存在概率、掩码、失真与抑制的取舍——都在这里以最纯粹的形式出现。

02两个信噪比与一个记分板入门

一句话版

γ 看得见但含随机起伏，ξ 看不见但决定一切。而误差可以严格拆成语音失真和残留噪声两块，二者正交——这是全书的记分板。

整套理论只需要两个量，而它们的区别是全书最重要的一件事：

② 后验信噪比 γ 与先验信噪比 ξ

后验信噪比看得见，但含噪声的随机起伏​γk,l​=λv​(k,l)∣Yk,l​∣2​​​先验信噪比看不见，必须估——这是全部难点​ξk,l​=λv​(k,l)λs​(k,l)​​​

γ 是这一帧实际观测到的功率比——它看得见，但它含着噪声本身的随机起伏：即使语音完全不在，γ 也会在 1 附近上下跳（平稳高斯噪声下，10log₁₀γ 的标准差恰好是 5.57 dB）。ξ 是期望意义上的功率比——它才是"这里到底有多少语音"，但它看不见，必须估。08 节整节在讲怎么估它。

增强的误差不是一个数，是两件不同的事：

为什么不用 SI-SDR 就好了

SI-SDR 也是把两项加在一起，而且它对整体尺度不敏感——这在源分离里是优点（不关心音量），在增强里是缺点（整体压低 6 dB 是一种真实的、听得出来的缺陷，而 SI-SDR 看不见它）。

18 节会看到 SI-SDR 与下游任务表现的相关系数是 −0.57——方向是反的。

01为什么说 γ 含着"噪声本身的随机起伏"？能量化吗？

看答案

能，而且有闭式。平稳高斯噪声的周期图 |V|² 服从 λ/2·χ²₂，也就是指数分布。取 10log₁₀ 之后标准差恒为 10/ln10·π/√6 = 5.57 dB。也就是说在纯噪声区域，γ 会在 ±5.6 dB 的范围里随机跳，而这个跳动和语音在不在没有关系。07 节会看到，音乐噪声就是这个跳动被增益放大的结果。

02语音失真和残留噪声，哪个更伤？

看答案

听感上普遍认为语音失真更伤——残留噪声只是"背景吵"，而语音失真会改变话本身的音色和清晰度。这也是为什么实践中的参数（谱底、最小增益）都是在牺牲噪声抑制来换失真。但 19 节会看到，对下游任务来说这个结论还要再打个折扣。

03时频变换与延迟预算入门

一句话版

算法延迟 = 一个窗长 + 一个帧移。耳机档只有 4 ms 的窗可用，连基频谐波都分不开（需要 30.8 ms）。这个约束比任何算法选择都硬。

所有方法都在 STFT 域做，所以先把变换的账算清楚。

④ 完美重构条件

l∑​w2(n−lR)=1满足 COLA，可完美重构平方根汉宁窗+50% 重叠​​浮点精度极限实测重构误差 −312 dB​​

平方根汉宁窗 + 50% 重叠满足 COLA，分析-合成是严格可逆的。实测重构误差 −312 dB，已经是双精度浮点的极限。这一点很重要：后面所有的失真都来自增益，不来自变换。

⑤ 算法延迟与频率分辨率

Talg​=要等窗填满Nwin​​​+块处理R​​汉宁窗主瓣宽度Δf=Nwin​4fs​​​​才分得开 130 Hz 的相邻谐波Δf<f0​⇒Nwin​≥493 点=30.8 ms​​

延迟是两块：要等一个完整的窗填满（512 点 = 32 ms），加上块处理的一个帧移。帧移变小不会降低延迟——延迟由窗长决定，帧移只影响算力。这一条经常被搞错。

耳机那一档差了将近一个数量级。这意味着在那一档上，"利用谐波结构"这条路根本走不通——一整类方法直接出局。

为什么耳机的延迟预算这么苛刻

两个原因，都和算法无关。

① 梳状效应：佩戴不密闭时，外界声音会直接漏进耳道，和处理后的声音叠加。两者延迟差几毫秒就会形成梳状滤波，音色明显发生变化。

② 自声延迟感：说话人自己的声音通过骨导瞬间到达，而通过设备的那一路晚几十毫秒回来，会产生明显的不适感（和打电话时听到自己回声是同一件事）。

所以这一档的预算是物理和生理决定的，不能靠"用户会习惯"绕过去。

低延迟的另一条路：滤波器组

STFT 不是唯一选择。低延迟系统常用多相滤波器组：用一组 FIR 分析滤波器把信号分到若干子带，延迟由滤波器阶数决定，可以做到远小于"等价频率分辨率的 STFT"。

代价是子带之间不正交、有混叠，重构不是完美的；而且子带数通常只有 32–64，频率分辨率比 STFT 粗得多。但在 2–5 ms 的预算里，它往往是唯一能用的结构。

01帧移取窗长的 1/4 而不是 1/2，延迟会变吗？

看答案

基本不变。延迟 = 窗长 + 帧移，帧移从 N/2 变成 N/4 只省下 N/4，而窗长那一项没动。算力倒是翻倍了。要降延迟只能缩窗，这是没得商量的。

02那为什么还要用高重叠？

看答案

两个理由。一是增益随时间变化时，重叠越高、合成信号里的不连续越少；二是 11 节会看到，重叠带来的冗余能稍微纠正错误的相位——不过实测这个收益只有 0.46 dB，比我原先预期的小得多。

04谱减与它的两个补丁入门

一句话版

谱减是最朴素的想法，也是唯一一个会产生剧烈音乐噪声的方法——残差起伏 17.9 dB，是理论零点的 3.2 倍。过减和谱底这两个补丁，是在拿语音失真换它。

想法一句话就说完：既然 |Y|² ≈ |S|² + λ_v，那就把 λ_v 减掉。

⑥ 功率谱减

∣S^∣2=max(∣Y∣2−αλv​, βλv​)⟹Gsub​=max(1−γα​, β02​)​两个纯听感补丁α=过减β0​=谱底​​

为什么它会产生音乐噪声

问题出在"减完可能是负数"。纯噪声区域里 |Y|² 在 λ_v 附近随机跳（02 节：标准差 5.57 dB），于是有些格子减完是正的、有些是负的。负的被截成零，正的留下来——留下来的就是一个个孤立的谱峰。

这些孤立谱峰在时间上随机出现、随机消失，每一个都是一个短促的纯音。听起来像有人在远处随机敲玻璃杯，所以叫"音乐噪声"。

谱减在今天还值得学吗

值得，但不是为了用它。

它是理解后面所有方法的最短路径：维纳、MMSE-STSA、log-MMSE 全都可以看成"用不同的方式解决谱减暴露出来的那个问题"。而神经网络预测的掩码，本质上也是在做同一件事——只不过它是从数据里学出增益曲线，而不是推出来的。

01过减因子 α 和谱底 β₀，该先调哪个？

看答案

先调 β₀。谱底决定了"最安静能安静到什么程度"，它同时抑制音乐噪声和呼吸效应，而且对语音失真几乎无害。α 是在拿语音失真换噪声抑制，调过头很难听出来（因为失真是渐进的），所以应该保守。实测总误差最小在 α = 3，但听感上通常取更小的值。

02为什么谱减要在功率域做，不在幅度域？

看答案

因为 |Y|² ≈ |S|² + λ_v 这个近似只在功率域成立（前提是 S 和 V 不相关）。幅度域的 |Y| ≈ |S| + √λ_v 是错的。实践中也有人用"幅度谱减"（指数取 1 而不是 2），那是一个经验性的变体，不是推导出来的。

05维纳：最小均方的那一支进阶

一句话版

维纳增益 ξ/(1+ξ) 是"两个高斯"假设下的最优解。它的问题不在最优性，在于低 ξ 处 G ≈ ξ——ξ 抖多少 dB，增益就抖多少 dB。

01既然 log-MMSE 更好，为什么还有人用维纳？

看答案

算力。维纳是一次除法，log-MMSE 要算一个指数积分加一次指数。在定点 DSP 上，E₁(ν) 通常要查表 + 插值，是整条链路里最贵的一步。在算力紧张的场合（助听器、超低功耗），维纳 + 一个好的谱底仍然是主流。

实测：同样是谱减 α=1，输入 0 dB 时起伏 18.00 dB，输入 10 dB 时 17.75 dB——数值差不多，但后者的绝对能量被语音盖住了，所以听不太出来。

① 为什么 α=0.98 的降噪听起来"特别干净"。不是因为它平滑得好，是因为低于 6.75 dB 的分量被整个抹掉了，一点残留都没有。

那该怎么用

① 把 α 当成"捕获阈值"来调，而不是"平滑强度"。你真正在选的是"多弱的语音分量要保留"。

② 对宽带、需要保留细节的场景（音乐、高保真通话），α 取 0.9–0.95，配一个较高的谱底。

③ 对只要"干净"的场景（语音通话），0.98 合适，但要接受辅音会被削。

④ 想要平滑又不想要开关效应，就别用这个递归——用一个显式的时间平滑（比如对 log ξ 做一阶低通），它没有这个双稳态。代价是音乐噪声抑制得没那么彻底。

前面所有公式里的 λ_v 都当成已知。现在把它估出来。

MCRA 系慢，是原理性的

01IMCRA 比 MCRA 好在哪？

看答案

两轮。第一轮先用 MCRA 得到一个粗的噪声估计，据此把明显有语音的时频点标出来；第二轮只在剩下的点上做平均。这样语音泄漏进噪声估计的量明显减少——实测语音段偏差从 +0.95 dB 降到 +0.45 dB。代价是它继承了第一轮的追踪延迟。

02噪声估计偏高和偏低，哪个更糟？

看答案

偏高更糟。偏高意味着 γ 被低估，于是 08 节那个捕获阈值把更多频点判成"没有语音"并抹掉——语音被啃掉。偏低只是残留噪声多一点。

这就是为什么所有估计器都倾向于保守（偏低），也是为什么 MS 的偏差补偿因子是"乘一个大于 1 的数"而不是更大的数。

10语音存在概率与 OM-LSA深入

一句话版

把 04 节那个纯听感补丁（谱底）换成一个有推导的东西：按"这一点有语音的后验概率"在完整增益和最小增益之间插值。

到这里为止，所有的增益都假设语音一定存在，只是强弱不同。但在纯噪声区域，正确的答案不是"增益很小"，是"根本没有语音"。把这件事写进模型，就是语音存在概率。

⑮ OM-LSA：按语音存在概率加权

GOM-LSA​=[Glog​]p⋅[Gmin​]1−p这一点有语音的后验概率p=Pr[H1​∣Y]​​只是换了个推导来路Gmin​ 就是谱底​​

这是一个几何加权：在对数域上，最终增益是 log-MMSE 增益和最小增益的线性插值，权重是 p。p → 1 时退化成 log-MMSE，p → 0 时退化成谱底。于是 04 节那个纯粹的听感补丁，在这里有了推导。

p 怎么算

用贝叶斯公式。设先验 P(H₁) = q，两个假设下 Y 的分布都已知（高斯），于是后验有闭式：

语音存在概率的实现

# 似然比
Lam = (1 - q) / q * np.exp(nu) / (1 + xi)
p   = 1.0 / (1.0 + Lam)

# 先验 q 本身也要估，常见做法是按"软判决"的历史平滑：
#   q(l) = beta * q(l-1) + (1-beta) * p(l-1)
# 或者按频带、按 SNR 分段给固定值（更稳，产品里常用）
为什么它在工程上重要

不是因为指标更好——实测 OM-LSA 和 log-MMSE + 一个调好的谱底，客观指标上差别很小。

重要的是它把"谱底"这个魔法参数换成了两个有含义的参数：最小增益 G_min（你愿意让噪声漏出多少）和语音存在的先验 q（这个场景里语音占多大比例）。这两个参数可以按场景、按频带分别设，而且设错了知道错在哪。

另外，p 这个量本身很有用：它可以直接拿去做 VAD、做噪声估计的更新门控（09 节的 MCRA 用的就是它的简化版）、甚至传给下游当作置信度。

别把 G_min 设成 0

把最小增益设成 0（完全静音）在指标上最好看：残留噪声是零，SegSNR 最高。但听感上这是最糟的选择之一——背景噪声忽有忽无，比持续的底噪难受得多（这在通话里叫"呼吸效应"）。

经验值：G_min 取 −12 到 −18 dB。再低就开始出现呼吸感，再高噪声抑制量不够。

顺带：这也是 04 节那张谱底表里，客观指标一路变差而听感一路变好的那个区间。

我原以为"短窗系统可以不管相位"，实测否掉了

流传很广的说法是：重叠相加有冗余，同一个样点被多帧覆盖，所以错的相位会被邻帧"平均掉"。按这个说法，重叠越高、窗越短，相位就越不重要。

窗长 4 ms → 128 ms（跨 32 倍）：11.63 → 12.49 dB

方向是对的，但量级太小——0.46 dB 撑不起"可以不管相位"这个结论，而且算力要翻 8 倍。

合起来的结论和我原先的假说相反：相位重不重要，几乎只由信噪比决定，和变换参数关系很小。

为什么复数掩码难训

三个原因，都很实在：

  • 值域无界。S/Y 在 |Y| 很小的地方会爆掉。实践中要做压缩（常见的是双曲正切压缩到 [−K, K]），而压缩函数本身是一个需要调的东西。
  • 相位没有平滑结构。幅度谱在时频上是平滑的、有共振峰有谐波，网络容易学；相位在相邻频点之间跳变（除非做群延迟或相位展开），看起来接近随机——网络很难从这样的目标里学到东西。
  • 相位误差和幅度误差不可比。在 |S| 很小的地方，相位怎么错都无所谓；在 |S| 很大的地方，相位错一点就很难听。直接对复数做均方误差，等于在这两种情况上用了同样的权重。
相位敏感掩码：一个便宜的折中

PSM = (|S|/|Y|)·cos(∠S − ∠Y)。它仍然是一个实数掩码，但它的取值考虑了相位差：相位差大的地方，掩码值被 cos 压小甚至为负。

好处是训练和 IRM 一样简单，而它在均方误差意义下是"带噪相位下的最优实数掩码"——也就是说它拿到了 11 节那个"只改幅度的上限"的最优点。

它拿不到的是相位本身那 6.60 dB。要拿那部分，只能上复数或时域。

另一条路：时域

Conv-TasNet 那一系干脆不用 STFT：用一个学出来的一维卷积当"编码器"，在那个域里做掩码，再用转置卷积解码。

它绕开了相位问题——因为学出来的表示里没有"幅度"和"相位"的区分。代价有两个：一是编码器的窗通常很短（2 ms 量级），按 03 节的分析，这一档分不开谐波；二是它的可解释性完全消失，出问题时无从调起。

相位重建（从幅度反推相位）在增强里基本没用

Griffin-Lim 那一类算法能从幅度谱迭代出一个"一致的"相位。在语音合成里它有用（因为那里根本没有相位可用）。

在增强里没用，原因是：你手上已经有一个相位了（带噪相位），而它在中高信噪比下已经相当接近真值。Griffin-Lim 迭代出来的相位只保证"自洽"，不保证"正确"，实测往往比直接用带噪相位更差。

它唯一有意义的用法是在极低信噪比下（带噪相位接近随机时）做几次迭代，而那时你面临的问题已经不是相位了。

我原以为上界高的那个至少不会更差

错得很彻底。上界和实得的排序几乎是反的：

上界最低的 IRM（14.10 dB）实得最高（11.31 dB），兑现 80.2%；上界是完美重建的复数掩码，实得只有 8.90 dB，兑现 25.4%。

原因不难说：sigmoid 把输出钉在 [0,1]，这个先验正好是对的——它免费提供了"增益不会放大信号"这条约束，网络不用花容量去学。而复数掩码要同时回归一个重尾的实部和虚部，网络的容量先去对付那些极端值了。

工程上的读法："这个参数化的上界更高"不是选它的理由，"在你的容量下兑现率更高"才是。而兑现率只能测，不能推。

这组实验能说什么、不能说什么

网络只有两个隐层、111,522 参数，训练 3000 步。兑现率是容量的函数——大模型 + 长训练下复数掩码确实能超过实数掩码，公开结果里的增益大约 0.5–1.5 dB SI-SDR。

所以可外推的不是"复数掩码不行"，而是三件事：① 上界的排序和实得的排序可以是反的；② 有界先验在小容量下是净收益；③ 重尾目标需要压缩，而压缩本身只补回一小部分。

经典方法只能衰减：它的输出永远是输入的一个衰减版本，不可能凭空产生内容。

神经网络可以。当它学到"这种上下文里通常有一个高频摩擦音"时，它可能在实际没有的时候把它补出来。在感知损失或对抗训练下这个倾向更强，因为那些损失奖励"像语音"。

对通话来说这是可接受的（听起来更自然）；对司法取证、医疗记录、语音识别前端来说这是灾难——你无法分辨一个音是真的还是补出来的。

判断方法：在纯噪声段上跑，看输出里有没有类语音的结构。经典方法这里一定是干净的衰减，神经方法不一定。

实务上的做法是按类别均衡采样，而不是按时长。这一条在代码里只是一行，在效果上差很多。

合成数据 vs 真实录音

绝大部分训练数据是合成的：干净语音 + 噪声 + 混响，按公式混。这是必须的——你拿不到"同一句话的干净版和带噪版"的真实配对。

它引入的偏差有两个：① 真实场景里说话人会提高音量、改变发音（Lombard 效应），而合成数据里干净语音是安静环境录的；② 真实的噪声和语音在空间上不独立（都经过同一个房间、同一个麦克风），而合成时它们是独立的。

这两条都无法靠增广完全消除。所以上线后的真实回流数据——哪怕没有配对标签——仍然是最值钱的资产（可以用来做域适应或半监督）。

看答案

02训练数据，是该加时长还是加种类？

看答案

加种类。同一个测试条件上，单一噪声的数据量翻 4 倍值 0.36 dB，把噪声从一种换成四种值 1.16 dB。并且要按类别均衡采样而不是按时长——否则网络会学到"默认噪声是平稳的"这个先验。

03为什么消融里混响这一维测出来是零？能下结论说混响不用管吗？

看答案

不能。这个实验的参考信号是带混响的干净语音，也就是只要求降噪、不要求去混响。在这个任务定义下混响不是瓶颈；一旦把参考信号换成无混响的干净语音，混响立刻变成主角。消融的排序依赖于任务怎么定义，这是读任何消融表都要先问的。

04特征要不要做逐句归一化？

看答案

要，但理由和一般说的不一样。实测它值 1.24 dB，而它不是靠"抗电平变化"赚到的——关掉归一化之后，漏掉电平覆盖的代价还是接近零。它买到的是输入分布在每一句里都稳定，让同样容量的网络不必为分布漂移留冗余。注意必须用因果递归统计量（16 节）。

01合成的训练数据和真实录音的差距，能靠增广补上吗？

看答案

部分能。加噪、混响、编解码、变速这些都可以合成。补不上的是两件事：① Lombard 效应——人在吵的环境里会提高音量、改变发音，而你的干净语音是安静环境录的；② 噪声和语音的空间相关性——真实场景里它们经过同一个房间和麦克风。这两条只能靠真实回流数据做域适应。

02线上回流数据没有配对标签，怎么用？

看答案

三条路。① 域适应：用回流数据的统计量（比如各频带的长时功率谱）去调整合成数据的分布。② 半监督：用现有模型给回流数据打伪标签，挑置信度高的加入训练。③ 只用噪声：从回流里切出纯噪声段，加进噪声库——这是最简单也最有效的一条，因为瓶颈就在噪声的种类。

那前端到底该怎么做

四条，按优先级：

① 如果下游是识别或声纹，先试试不做增强。现代声学模型本身对噪声有相当的鲁棒性，而它们训练时见过的是带噪音频，不是"被增强过的音频"。

② 如果必须做，让下游模型也见过增强后的音频。这比增强本身重要得多——它把"失配"变成"匹配"。

③ 优先用线性处理（波束形成、回声消除）。它们改变信噪比但不改变谱的结构。

④ 如果只能用非线性增强，把它的强度调弱。表里"欠抑制"那一行是所有处理里下游最好的——这不是巧合。

这一节的实验有它的局限

这里的说话人嵌入是 MFCC 的均值和标准差，而且是文本相关的（所有人念同一句）。真实的 ECAPA 或 x-vector 嵌入要鲁棒得多。

所以绝对数值不能直接搬。但方向和相对顺序是可信的：非线性增强引入了一个与训练条件不同的信道，而任何基于统计的下游模型都会因此付出代价。这一条在真实系统上被反复验证过。

01如果下游是 ASR，最省事的做法是什么？

看答案

02线性处理（波束形成、回声消除）为什么就没有这个问题？

看答案

因为它们不改变谱的结构，只改变各成分的相对强度。一个固定的线性滤波器作用在语音上，相当于一个信道——而下游模型对信道的鲁棒性本来就比对非线性伪影强得多（倒谱均值归一化这一类手段就是专门对付信道的）。

看答案

因为算力 = 每帧乘加 × 帧率，而帧率 = 采样率 / 帧移。实测 32.30 MMAC/s vs 7.94 MMAC/s，差 4.1 倍。要省算力得省帧率（滤波器组、跨帧复用），不是把模型做小。

03在低延迟档，神经方法相对经典方法的优势是更大还是更小？

看答案

更大。实测耳机档经典 +3.87 dB、网络 +5.31 dB；会议档两者打平（+7.02 vs +7.05）。机制是网络能用时间上下文补一部分短窗丢掉的频率分辨率，而逐点的增益函数没有这个渠道。

我原以为"级联"那一招在这里也管用

《声纹与唤醒手册》15 节里，一级小模型常开、二级大模型只在被叫醒时跑，省了 52 倍功耗。我原本以为增强也能这么干：平时用便宜的方法，检测到"难的情况"再切到贵的。

不成立，原因是增强没有"绝大多数时候不用做"的不对称性。唤醒的收益来自 99.7% 的时间里一级说"不是"就够了；而增强是每一帧都要输出的，没有可以跳过的时候。

能做的是另一种：按噪声条件切换参数（安静时弱抑制、嘈杂时强抑制），或者按频带分配算力（低频细致、高频粗略）。这两条都有效，但它们省的是 2–3 倍，不是 50 倍。

一个自查清单

上线前把这几件事跑一遍，多数问题会提前暴露：

① 在纯语音（无噪声）上跑：输出应该几乎等于输入。如果 LSD 明显不为零，说明系统在没有噪声时也在乱动。

② 在纯噪声上跑：输出应该是均匀衰减的底噪。如果听到断续的音调，就是音乐噪声；如果听到类语音的结构，就是幻觉（15 节）。

③ 做一次噪声阶跃测试：中途把噪声提高 12 dB，看多久恢复（09 节）。

④ 做一次延迟实测：给一个冲激，量输出峰值的位置。不要相信文档里写的延迟。

⑤ 如果有下游任务，直接量下游指标（19 节）。

原因不神秘：波形保真类指标量的是"离干净波形有多远"，而填进去的是统计上对、样本上不对的内容——它必然增加波形误差，同时让谱的分布更像真的。这就是感知–失真权衡在最小实验里的样子。

"编出来了"这一栏才是幻觉的那个量

它从 0.31% 涨到 0.45%（1.5 倍）。绝对值很小——因为这个后处理被限制了"填不超过估计出的包络"。真正的生成模型没有这个约束，这一栏会大得多。

重点不在绝对值，在三件事：

① 它是单调上升的，而其余五个指标在同一区间里是改善的。也就是说，照着任何一个常用指标调 β，都会把这一栏推高。

② 没有任何常用指标在看它。SegSNR、LSD、STOI、PESQ 都会把"填进去的像样内容"算作改善或小的失真，没有一个会说"这段东西本来不存在"。

③ 它是预测式方法结构上不会犯的错。纯衰减的方法输出里的每一个成分都来自输入，所以在高风险场景（取证、医疗、法庭记录）里，"只会削"本身就是一条可以写进规格的保证。

所以"生成式增强"这条趋势该怎么读

不是"更好的降噪"，是换了一种错误。它把"删掉了"换成"编出来了"，而现有的评测体系只看得见前者。

落地上的三条推论：

① 要上生成式方法，评测体系得先改——至少加一个"输出里有多少成分不来自输入"的度量。上面那个"编出来了"是最粗糙的版本，但有它比没有好。

② 给机器听的那一侧（ASR 链路手册、声纹与唤醒手册）要格外小心：19 节已经量到增强的非线性会让下游变差，而生成式增强引入的是语音样的内容，下游分不出它是真的还是填的。

③ 反过来，给人听的、容错的场景（语音消息、会议回放）里，这组数据支持生成式：五个指标改善，代价是一个几乎没人在听的波形保真指标。

这组实验能说什么、不能说什么

填充方式只试了"按估计包络填成形噪声"这一种，而且被限制在估计出的包络以内；真正的扩散/流匹配模型的生成能力和幻觉风险都高一个量级。"编出来了"的绝对数值完全不能外推。

可外推的是结构：两类错误是此消彼长的；常用指标只看得见其中一类；以及因此而来的那条规则——按常用指标优化，会单调地把另一类错误推高。

采样与生成那一侧的细节见 TTS 合成手册，它那边量的是同一个硬币的另一面：合成时温度调高，分布更像真的，而单句的保真度下降。

看答案

02要上生成式增强，评测上先补什么？

看答案

补一个"输出里有多少成分不来自输入"的度量。实测现有指标里五个会随填充强度改善、只有波形保真那个变差，所以照着任何一个常用指标调，都会单调地把幻觉推高。最粗糙可用的版本：统计干净谱里接近静音、而输出里变显著的时频格子占比。

看答案

纯衰减的预测式。它的输出里每一个成分都来自输入，"只会削"本身是一条可以写进规格的保证。实测削过头那一档"编出来了"只有 0.26%，是三种方式里最低——代价是"删掉了" 46.8%，最高。这个取舍在这类场景里是对的。

一个我认为被高估的方向

"用更大的模型做单通道降噪"。

01为什么谱减会产生音乐噪声，而维纳不会（那么严重）？

看答案

谱减在纯噪声区做的是"减一个常数再截断"：|Y|² 随机跳动，有些格子减完为正、有些为负，负的被截零，正的留下来成为孤立谱峰。维纳的增益是 ξ/(1+ξ)，是连续的，不会硬截断。但维纳在低 ξ 处 G ≈ ξ，ξ 抖多少 dB 增益就抖多少 dB，所以它的起伏（9.89 dB）仍然显著高于理论零点（5.57 dB）。

02残差起伏读到 4.81 dB 和读到 5.57 dB，哪个更好？

看答案

不一定。4.81 dB 低于理论零点，说明残差被抹平了——可能是好事（log-MMSE 的情况），也可能是过度抑制（把该留的也压掉了）。这个量必须和噪声抑制量、可懂度一起看，18 节那张名次表就是这个陷阱的完整版本。

03判决引导的 α 从 0.95 调到 0.98，实际发生了什么？

看答案

不是"更平滑"。是捕获阈值从 6.00 dB 抬到 6.75 dB——更多的弱语音分量被整个抹掉了。听感上更干净（没有残留），代价是气声、擦音、元音的衰减尾巴被削。（08 节）

04噪声估计偏高和偏低，哪个后果更严重？

看答案

偏高。偏高 → γ 被低估 → 更多频点落到捕获阈值以下 → 语音被啃掉。偏低只是残留噪声多一点。这就是为什么所有估计器都设计得偏保守，也是为什么 MS 的偏差补偿因子不敢设得太大。（09 节）

05把帧移从窗长的 1/2 改成 1/4，延迟会降低吗？

看答案

基本不会。延迟 = 窗长 + 帧移，缩帧移只省下窗长的 1/4，而窗长那一项没动。算力倒是翻倍了。要降延迟只能缩窗。（03 节）

06只改幅度的方法，上限在哪？相位还值多少？

看答案

上限是"干净幅度 + 带噪相位"。在理想比值掩码之上再把相位换成干净的，输入 0 dB 时还能再拿 6.60 dB，输入 10 dB 时 5.17 dB。相位在低信噪比时更值钱——而那正是最需要降噪的时候。（11 节）

07短窗系统可以不管相位吗？

看答案

这个说法在这里没有被支持。重叠从 2× 加到 16× 只多拿 0.46 dB，窗长跨 32 倍只差 0.86 dB。相位重不重要几乎只由信噪比决定，和变换参数关系很小。（11 节）

08神经降噪比 log-MMSE 好在哪？只看 SegSNR 好像差不多。

看答案

SegSNR 上确实只差 +0.16 dB。差距在别处：LSD 5.69 → 3.40，STOI* 0.809 → 0.945。信噪比类指标看不见这个差距，而它恰好是听感和可懂度上最大的那部分。（13 节）

09要提升泛化，是加模型还是加数据？

看答案

加数据，而且是加种类不是加时长。实测：训练噪声从 1 种加到 3 种，在第三种没见过的噪声上涨了 1.59 dB；而换输出形式（参数多 34%）只换来 0.52 dB。（17 节）

10用 SI-SDR 当损失有什么副作用？

看答案

它优化波形对齐，而波形对齐由高能量部分主导。实测：残差起伏被压到 0.28 dB（极其平滑），但 STOI* 从 0.945 掉到 0.841、LSD 从 3.40 升到 5.59——低能量的谱细节（辅音、高频）被牺牲了。（15 节）

11我的降噪上线后，语音识别的词错率反而升高了。可能是什么？

看答案

最可能是两件事之一。① 失配：识别模型训练时没见过被这个前端处理过的音频。解法是让识别模型也见过（或者干脆不做增强）。② 非线性失真：19 节的实测里，每一种增强都让下游变差，而波形保真类指标是反相关的。先做一组"开/关增强"的下游对比，不要相信 SI-SDR。

12为什么 19 节里"欠抑制"是所有处理里下游最好的？

看答案

因为它改动最小。下游模型真正怕的不是噪声，是训练时没见过的谱形状。增强越激进，改得越多，失配越大。这也是"给机器听的增强要调弱"这条经验的来历。（19 节）
