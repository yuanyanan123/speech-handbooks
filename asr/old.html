01声音怎么变成数字入门

一句话版

麦克风把气压变化记成一串数字；但直接看这串数字什么也看不出来，必须切成小片、转到频率域，才能看到"音素长什么样"。

采样：为什么是 16 kHz

声音是空气压强随时间的起伏。麦克风每秒测量若干次，每次记一个数——这就是采样。奈奎斯特定理说：采样率必须至少是最高频率的 2 倍，才能无失真还原。

  • 语音的可懂度信息主要落在 300 Hz – 3.4 kHz（这就是电话带宽的由来）
  • 但 s sh f 这类清擦音的能量能到 8 kHz 以上，砍掉会明显影响辅音区分
  • 所以 16 kHz（可表示到 8 kHz）是 ASR 的标准权衡。音乐用 44.1/48 kHz，是因为人耳能听到 20 kHz

位深通常 16 bit，动态范围约 96 dB，足够覆盖从耳语到喊叫。所以 1 秒单声道音频 = 16000 个 16 位整数 = 32 KB。

分帧：为什么是 25 毫秒

整段波形没法直接分析——因为语音一直在变。但声道的形状变化很慢：舌头、嘴唇每秒大约动 10–20 次。在 25 毫秒这个尺度内，可以近似认为声道形状不变，这叫短时平稳。

帧移取 10 ms（帧之间有 15 ms 重叠），是因为最短的音素也有 30–50 ms，每 10 ms 采一帧才能捕捉到音素之间的过渡。于是 1 秒音频 = 100 帧，这个"每秒 100 帧"是整个传统 ASR 的时间单位。

为什么要加窗

直接把波形切断，断口处会产生突变，做 FFT 后表现为频谱泄漏（本来没有的频率成分冒出来）。所以每帧要乘一个两端平滑衰减的窗函数（汉明窗、povey 窗），让断口过渡自然。这是信号处理的常规操作，不是 ASR 特有的。

频谱：从"多大声"到"什么音"

每一帧做傅里叶变换，得到这 25 ms 内各个频率成分的强度。把连续很多帧的频谱竖着排起来、用颜色表示强度，就是语谱图——这是语音识别真正看的东西。

语谱图上能直接看出：元音有清晰的横向亮带（共振峰，由声道形状决定，是区分 a/i/u 的关键）；清辅音是一片高频噪声；爆破音前面有一小段空白（闭塞段）。后面所有的特征提取，都是在把语谱图压缩成更适合模型消化的形式。

02为什么难：五个绕不过去的问题入门

理解了这五个问题，后面每一代技术在解决什么就清楚了。

问题具体是什么谁来解决
① 长度不对齐 5 秒音频有 500 帧，对应的文字可能只有 10 个字。哪几帧对应哪个字？没人告诉你——训练数据只有音频和整句文字 HMM / CTC / RNN-T
② 语速可变 同一个"你好"，慢说占 80 帧，快说占 25 帧。模型必须对时间伸缩不敏感 HMM 的自环 / CTC 的重复合并
③ 协同发音 "你"里的 i 和"急"里的 i，声学上差别很大——因为前后音素改变了舌头的运动轨迹。音素没有固定长相 三音素 + 决策树 / 大感受野编码器
④ 同音歧义 "shi tang" 是"食堂"还是"试探"？声学上无法区分，只能靠上下文 语言模型 / 自注意力 / LLM
⑤ 噪声与信道 同一句话，手机录和会议室录，频谱差别可能比不同人说话还大 CMVN / 数据增广 / 大规模预训练
感受一下问题 ①

你有一段 5 秒录音，和它的文字"今天天气不错"。你怎么训练一个模型？

模型需要知道"第 137 帧应该输出什么"，但你手上只有整句。逐帧标注 500 帧是不可能的——1000 小时数据就是 3.6 亿帧。

三种解法，正好对应三代技术：
HMM —— 先用一个粗糙模型猜一个对齐，训练，再用更好的模型重新对齐，反复迭代（第 05 节）。
CTC —— 不猜了，把所有可能的对齐的概率加起来一起优化（第 08 节）。
Attention —— 让模型自己学会该看哪几帧（第 09 节）。

03怎么衡量好坏入门

WER / CER：错误率

用编辑距离算：把识别结果改成正确答案，最少需要多少次替换(S)、删除(D)、插入(I)。

错误率 = (S + D + I) / N        N = 参考文本的长度

英文按词算叫 WER，中文按字算叫 CER。

算一遍 
参考：今 天 天 气 不 错          N = 6
识别：今 天 天 汽 很 不 错

对齐：今 天 天 [气→汽] [→很] 不 错
      替换 1 次（气→汽）
      插入 1 次（很）

CER = (1 + 0 + 1) / 6 = 2/6 = 33.3%

注意错误率可以超过 100%——如果模型疯狂插入内容（幻觉），分子会比分母大。这也是第 24 节那个"字/秒比值"监控的由来。

RTF / RTFx：速度

RTF  = 处理耗时 / 音频时长      越小越快，RTF = 0.1 表示比实时快 10 倍
RTFx = 1 / RTF                  越大越快，榜单上常用这个

实时流式系统要求 RTF < 1，否则会越积越多。批量转写只看吞吐，RTF 0.02 意味着 1 小时音频 72 秒转完。

看榜单的常识

WER 是在相对干净的朗读/播客数据上测的。真实场景（远场、口音、噪声、专业术语）的差距和榜单顺序常常不一致。目前开源模型前十名的差距不到 1 个百分点，这个量级在真实场景里基本被淹没——选型该由许可证、语种、延迟、部署形态主导，不是 WER。

05第一代：GMM-HMM进阶

一句话版

把每个音素想象成一条流水线上的几个工位，语音一帧帧流过；HMM 负责决定"这一帧停在哪个工位"，GMM 负责判断"这一帧长得像不像这个工位该有的样子"。

HMM 解决的是对齐

把每个音素建成一个三状态的左到右模型（起、中、末）。每一帧要么停在原状态（自环，对应语速慢），要么前进一格。于是"5 秒音频对应 6 个字"这个问题，变成了"在一张状态图上找一条最优路径"。

P(X|W) = Σ_S  Π_t  a(s_{t−1}→s_t) · b_{s_t}(x_t)
              ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾   ‾‾‾‾‾‾‾‾
                 转移概率          这一帧像不像这个状态
算一遍 · Viterbi 对齐

4 帧音频，一个 3 状态音素

假设声学模型已经给出每帧在每个状态上的对数得分（越接近 0 越像）：

得分 bt=1t=2t=3t=4
s1 起−0.2−1.5−3.0−4.0
s2 中−2.5−0.4−0.8−2.2
s3 末−3.5−2.0−0.6−0.3

转移一律 log 0.5 ≈ −0.7。必须从 s1 起、在 s4 结束前到 s3。逐列递推，每格只保留最优前驱：

δ 累积t=1t=2t=3t=4
s1−0.2−2.4−6.1−10.8
s2−∞−1.3−2.8−5.7
s3−∞−∞−2.6−3.6
 
回溯最优路径： s1 → s2 → s3 → s3     总分 −3.6

得到的对齐： 第1帧属状态1，第2帧属状态2，第3、4帧属状态3
             ↑ 这就是训练下一轮模型所需要的"每帧标签"

这就是全部魔法：原本要枚举 3⁴ = 81 条路径，动态规划让它变成 3×4 = 12 次比较。真实系统里状态数几千、帧数几百，指数级变成 O(T·N²)——整条链能跑起来全靠这笔交易。

GMM 负责打分

每个状态挂一组高斯分布（典型 16–32 个），用来回答"这一帧的 39 维特征向量，有多像这个状态"。用多个高斯而不是一个，是因为同一个状态在不同说话人、不同语境下会有多个"典型长相"。

鸡生蛋问题怎么破

要模型才能对齐，要对齐才能训模型。解法是从最粗糙的假设冷启动，逐步精化：

等分对齐（把音频平均分给音素）   ← 明知是错的，但能启动
   → 训单音素模型 mono
   → 用 mono 重新对齐 → 训三音素 tri1
   → 用 tri1 重新对齐 → 训 tri2 (加 LDA+MLLT 变换)
   → 用 tri2 重新对齐 → 训 tri3 (加说话人自适应 fMLLR)

这条引导链在 Kaldi 里一步都省不掉，即使最终要训的是纯神经网络的 chain 模型——因为决策树和分子监督都要靠 GMM 的对齐来建。这也是端到端方案最想摆脱的负担。

两个错误但必要的假设

一阶马尔可夫：下一状态只取决于当前状态 → 状态驻留时间被迫服从几何分布，而真实音素时长更接近伽马分布。
观测条件独立：每帧的得分只取决于当前状态，与其他帧无关 → 相邻帧明明高度相关。
两个假设都是错的，但没有它们那个 Σ_S 无法分解成动态规划。后面所有的补丁——delta 特征、拼帧、声学缩放因子——都是在掩盖这两个假设的破绽。

06第二代：DNN-HMM 混合进阶

一句话版

2012 年前后，把 GMM 换成神经网络，错误率直接掉 20–30%。整个 HMM/词典/WFST 结构原封不动——所以叫"混合"系统。

神经网络的优势在于：它可以一次看几十帧（拼帧或大感受野），而 GMM 只能看一帧；它能自动学特征组合，而 GMM 要求特征各维不相关。但接进去有一个必须处理的换算问题。

伪似然：hybrid 系统的核心 trick

神经网络训练成分类器，输出的是后验概率 P(状态|特征)。但 HMM 的公式里要的是似然 p(特征|状态)。贝叶斯反演：

p(x|s) = P(s|x) · p(x) / P(s)

p(x) 与 s 无关，在 argmax 中是常数可以丢掉，于是：

scaled likelihood ∝ P(s|x) / P(s)      ← 必须除以状态先验

先验 P(s) 就是训练对齐里各状态出现的频率，直接数出来。

忘了除先验会怎样

静音、弱化元音这些高频状态会过度吸引解码路径，识别结果变成大片空白。这是新手接 DNN 到 Kaldi 最经典的事故。

那个 0.1 是怎么回事

解码时要设 --acoustic-scale=0.1，等价于给语言模型放大 10 倍。原因是：条件独立假设让每帧的似然重复计入了相关信息，声学得分的动态范围被严重高估，必须人为压缩才能和语言模型得分平衡。这个超参数的存在本身就是模型错误设定的证据——到了第三代 chain，它变成 1.0，因为序列级训练把尺度学对了。

07第三代：chain / LF-MMI深入

一句话版

训练目标从"每帧猜对状态"改成"整句比所有错误答案得分高"，同时把音素最短时长从 3 帧放宽到 1 帧，帧率因此可以降 3 倍。三处改动必须一起做。

为什么逐帧交叉熵不够好

第二代的训练目标是"每一帧分类正确"。但两个毛病：① 对齐是 GMM 给的，可能是错的，一旦定死网络只能去拟合错误边界；② 逐帧正确 ≠ 整句正确，和最终的 WER 目标隔了很远。

序列判别训练直接优化"正确句子的后验"：

              P(X|W_正确)^κ · P(W_正确)
F_MMI = Σ log ──────────────────────────
              Σ_W P(X|W)^κ · P(W)         ← 分母：所有可能的句子

难点全在分母。传统做法是先训好 CE 模型，解码整个训练集生成 lattice 当分母的近似——三个阶段、几十小时、而且分母一旦生成就冻结了。

LF-MMI 的三处协同改动

1

拓扑：3 状态 → 1 个可发射状态

音素最少只占 1 帧（传统必须 3 帧）。这是降帧率的前提。

2

帧率：10 ms → 30 ms

音素典型时长 80–150 ms，30 ms 一帧仍有 3–5 帧，够用。计算量直接降 3 倍。

3

分母：换成音素级 4-gram 小图

08第四代：CTC 与 blank 的发明进阶

一句话版

与其猜"哪一帧对应哪个字"，不如把所有猜法的概率全部加起来一起优化。为了让这件事可行，需要发明一个特殊符号：blank（空白）。

blank 解决两个问题

模型每帧输出一个符号，最后把这串符号"折叠"成文字。折叠规则只有两步：先合并连续重复，再删掉所有 blank。

你你-好好好  →  合并重复: 你-好  →  删blank: 你好  ✓
  • 问题一：模型不确定时怎么办 → 输出 blank，表示"这一帧没有新内容"。静音、音素过渡段都可以输出 blank。
  • 问题二：叠字怎么办 → "好好"如果直接输出 好好 会被合并成一个"好"。所以必须写成 好-好，用 blank 把两个字隔开。这才是 blank 存在的真正原因。
算一遍 · CTC 的所有对齐

目标"你好"，4 帧，词表 {你, 好, -}

能折叠成"你好"的 4 帧路径，一共 15 条，全部列出：

--你好-你-好-你你好-你好--你好好 你--好你-好-你-好好你你-好你你你好 你你好-你你好好你好--你好好-你好好好

CTC 的损失函数是这 15 条路径的概率之和取负对数。模型不需要知道"你"具体在第几帧——它只需要让这 15 条路径的总概率最大。

怎么高效地加起来

穷举 15 条只是因为 T=4 很小；T=500 时路径数是天文数字。用前向算法：把目标序列扩展成 l' = [-, 你, -, 好, -]（每个字前后插 blank），然后逐帧递推"走到位置 s 的路径数"。

αs=0
「-」		s=1
「你」		s=2
「-」		s=3
「好」		s=4
「-」
t=111000
t=212110
t=313341
t=4146105
 
总数 = α[4][s=3] + α[4][s=4] = 10 + 5 = 15   ✓ 与穷举一致

递推规则：α[t][s] = α[t−1][s]        停在原地
                  + α[t−1][s−1]      前进一格
                  + α[t−1][s−2]      跳过中间的 blank
                                     （仅当 l'[s] 是字且 ≠ l'[s−2]）

这里为了看得清用的是"路径计数"，真实训练里把 1 换成每帧的输出概率相乘即可，形式完全一样。复杂度从指数级降到 O(T × 2L)——和 HMM 的前向算法是同一个东西。

CTC 换来了什么，付出了什么

影响
得到不需要发音词典、不需要决策树、不需要 GMM 引导、不需要强制对齐。训练数据只要 音频 + 整句文字，新语种上手成本降一个数量级
得到天然单调对齐、天然流式，结构上不可能长篇幻觉
代价条件独立假设：每帧输出彼此独立，模型内部没有语言模型能力。"食堂"和"试探"分不清时，CTC 自己救不了自己——所以要外挂 n-gram（第 15 节的 TLG）
代价峰值对齐：CTC 倾向于在音素中间某一帧突然输出、其余全是 blank。所以它给的时间戳是尖锐且偏移的，不能用于精确的音素级强制对齐

09第五代：RNN-T 与 Attention进阶

一句话版

CTC 的病是"每帧输出互相不知道"。RNN-T 加一个网络专门读已经输出的文字（相当于把语言模型吸进模型里）；AED 则让解码器自己决定该看哪几帧。两条路线在 Conformer 编码器上汇合。

RNN-T：在一张网格上走路

三个组件，分工清晰得像一个人在听写：

组件干什么类比
Encoder把音频帧编码成表征耳朵：听到了什么
Prediction Network只看已经输出的文字，预测下一个字脑子里的语言直觉：内置 LM
Joint Network把两者合并，输出"下一个字是什么，或者 blank"拍板

解码过程可以想象成在一张 T × U 的网格上走路（T 是帧数，U 是字数）：

       字 ↑
        好 │  ·   ·   ·   ●───▶ 完成
           │          ╱
        你 │  ·   ●──▶·   ·
           │    ╱
        ∅  │  ●──▶·   ·   ·
           └────────────────────▶ 帧
             t1  t2  t3  t4

  向右 → 输出 blank，消耗一帧（"还没听够"）
  向上 ↑ 输出一个字，不消耗帧（"这里可以连出好几个字"）

关键差别：向上不消耗帧，所以一帧可以吐出多个字；而且每一步都能看到已输出的文字，条件独立假设被打破了。代价是训练时要在整个 T×U 网格上做前向后向，显存占用远高于 CTC。

目前端侧首选基本都是 transducer 路线：zipformer-transducer（icefall / sherpa-onnx）、Parakeet TDT。

AED：让模型自己决定看哪里

Attention-based Encoder-Decoder 走另一条路：解码器每要输出一个字，就对整段音频的所有帧算一次权重，加权求和后再决定输出什么。这个权重就是注意力。

  • 优点：没有任何对齐约束，精度上限最高，天然能利用全局上下文消歧
  • 缺点：必须看完整句才能开始（不能流式）；没有单调约束，所以会幻觉——这正是第 24 节要治的病

WeNet 的 U2++：两条路线合一

                  ┌─▶ CTC 线性层 ──▶ 第一遍：prefix beam search → n-best
fbank ─▶ Conformer 编码器
                  └─▶ Attention Decoder ─▶ 第二遍：对 n-best 重打分

妙处在于第二遍不是自回归生成，是 rescoring——候选已由 CTC 给出，decoder 只需一次并行的 teacher-forcing 前向，延迟可控。这样既拿到了 CTC 的流式能力，又拿到了 attention 的精度。

配套的 dynamic chunk training：训练时每个 batch 随机采样 chunk 大小（含 ∞），注意力掩码随之限制。结果是一套权重学会了所有延迟档位——部署时 chunk=16 就是 640 ms 流式，chunk=∞ 就是全句最高精度，换延迟只改配置不重训。

U2++ 再加一个从右到左的 decoder，训练时逼编码器同时编码过去与未来，rescoring 时双向融合，相对提升约 10%。

10第六代：预训练与弱监督入门

一句话版

标注数据永远不够，但无标注音频和网上的字幕多得是。两条路：自监督（做完形填空，学会"语音长什么样"）和弱监督（把几十万小时质量参差的字幕硬吃下去）。

自监督：wav2vec 2.0 的完形填空

没有文字标注也能学。做法是把一段音频的某些片段遮住，让模型根据上下文猜被遮住的地方"是什么"。

原始音频 ──▶ 卷积编码器 ──▶ 一串向量
                              ↓ 随机遮住一部分
                          Transformer
                              ↓
              猜出被遮住位置的"离散单元"是哪个
              （单元通过量化自动学出来，不是人定义的音素）

这样学出来的表征已经隐含了音素结构。之后只需几十小时甚至十分钟的标注数据微调，就能达到过去几百小时才有的效果。对低资源语种是革命性的。

弱监督：Whisper 的暴力路线

反方向：不搞自监督，直接从网上收集 68 万小时音频-字幕对——质量参差、有错、有机器翻译的，但量足够大。多任务一起训：

输入音频 + 任务提示 token：
  <|zh|><|transcribe|><|notimestamps|>    中文转写
  <|zh|><|translate|>                      中译英
  <|nospeech|>                             判断有没有人说话

结果是极强的鲁棒性和 99 语种覆盖，代价是学会了字幕数据里的坏习惯——"听不清就补一句常见的"，也就是幻觉的根源（第 24 节）。

别默认选 Whisper 做中文

Whisper 的中文数据占比不高，标点和数字规范化都弱。它的价值在生态厚度（MIT 许可、99 语种、faster-whisper / whisper.cpp / WhisperX 全套衍生），不在中文精度。中文项目该看 FireRedASR、Qwen3-ASR、Paraformer（第 19 节）。

11第七代：LLM-ASR入门

一句话版

既然大语言模型已经很懂中文了，就别让 ASR 再从头学语言了——把语音编码器的输出接进 LLM，转写变成"看着这段声音，把它写出来"的一次条件生成。

音频 ─▶ 语音编码器 ─▶ 适配层 ─▶ ┐
                                ├─▶ 大语言模型 ─▶ 文字
系统提示 / 上下文 / 热词表 ─────┘

这个架构带来三件过去做不到的事：

  • 上下文直接进 prompt。"以下音频涉及：卡尔曼滤波、无刷电机、FOC"——热词偏置从需要改解码器变成了写一句话（对比第 23 节的四层方案）
  • 语言知识免费继承。同音歧义、专业术语、书面语规范，LLM 本来就会
  • 顺带做别的。转写+翻译+摘要+说话人分离可以在一次生成里完成

代价是参数量（2–3 B 起步）、延迟，以及幻觉从"补一句字幕"升级成"编一段通顺的话"——更难被察觉。目前榜单头部基本都是这一类：ARK-ASR-3B、Granite Speech、Cohere Transcribe、Canary-Qwen、Qwen3-ASR。

脉络到这里的总结

三十年的主线是把语音知识从模型结构里搬到数据里。第一代把音素、词典、上下文规则全写进结构；到第七代，这些全部由数据和参数隐式承担。但注意两件事没有消失：WFST 作为外挂语言模型的手段还在（因为纯文本永远比音频多），Kaldi 式的强制对齐还在（因为端到端给不出精确的音素边界）。

12特征提取：本质是同态解卷积进阶

一句话版

说话 = 声带的嗡嗡声（激励）经过口腔这个滤波器（声道）。识别只需要滤波器，不需要嗡嗡声。倒谱变换就是把这两者分开的数学手段。

语音的产生模型是源-滤波器：x(t) = e(t) * h(t)，声门激励卷积声道冲激响应。h 决定音素，e 决定基频和说话人。麻烦在于卷积很难拆开——除非换个域：

x(t) ──FFT──▶  E(ω)·H(ω)        卷积 → 乘法
     ──log──▶  logE + logH      乘法 → 加法      ← 关键一步
     ──DCT──▶  倒谱域，二者落在不同"倒频率"区间

取前 13 维 = 在倒谱域做低通滤波 = 只保留缓慢变化的谱包络（声道）。被丢掉的高倒谱区那个尖峰，正是基频。

Mel 滤波器组：模拟耳蜗

中间那层做的是另一件事：把线性频率轴弯成对数尺度，模拟耳蜗基底膜的临界带宽——低频分得细，高频分得粗，因为人耳就是这样。

m = 2595 · log₁₀(1 + f / 700)

23 个三角滤波器把 257 维幅度谱压到 23 维，顺带做了谱平滑
CMVN 为什么有效

信道（麦克风、房间）是一个线性滤波器，卷积在 log 谱域变成加性常数。所以在倒谱域减去均值，就精确地消掉了信道——不是经验性的归一化，是有严格推导的。这是倒谱表示白送的好处。

DCT 的真实动机，以及它为什么过时了

教科书说 DCT 是为了"去相关"，但去相关是为了谁？为了 GMM——GMM 用对角协方差（满协方差参数量爆炸且数据不够），要求特征各维近似不相关。

到了 DNN 时代这个约束消失：网络不怕相关特征，还能利用局部谱结构。所以现代配方（chain 的 hires、WeNet 的 fbank）用 40 维不截断，DCT 退化成一个普通的正交变换，甚至干脆不做。同理，delta/delta-delta 特征也消失了——它本来是为了给"条件独立"的 HMM 偷偷塞进时间上下文，而 DNN 有几十帧的感受野，不需要这个补丁。

13决策树与 senone深入

一句话版

三音素有 800 万种，训练数据只覆盖极小一部分。决策树把它们聚成几千类。树是索引，GMM/DNN 是索引指向的打分器——两者常被混为一谈，其实完全不同。

为什么必须绑定

词 → 音素（词典 L）→ 三音素（协同发音）→ 绑定状态 senone

中文约 200 音素 → 200³ = 8×10⁶ 个三音素
                → 绝大多数在训练集里出现 0 次或个位数次

树问的是符号，不是特征

这是最容易误解的地方。你熟悉的 CART / 随机森林是特征空间的分割器，节点上问 x[3] > 0.5?。而音素决策树的节点上问的是：

"左邻音素是不是鼻音？"
"右邻音素是不是前元音？"
"当前是 HMM 的第几个状态？"

输入：(左音素, 中心音素, 右音素) + 状态位置   ← 一组符号
输出：一个整数 pdf-id                          ← 索引
整个过程不看任何一帧特征
决策树GMM / DNN
定义域 → 值域phones → intR⁴⁰ → R⁺
作用定义"总共要区分多少类"给每一类打分
参数无（确定性映射）μ, Σ, 权重 / 网络权重
chain 模型里还在GMM 已被 DNN 取代

决定性的证据：chain 模型里一个 GMM 都没有，但决策树照样要建，网络输出层维度就是叶子数。如果"GMM 就是决策树"，树该跟着消失才对。

树是怎么长出来的

分裂准则是单高斯似然增益，对角协方差下有闭式解：

L(S) = −0.5 · γ(S) · [ Σⱼ log σ²ⱼ(S) + d(1 + log2π) ]
ΔL   = L(S_yes) + L(S_no) − L(S)      贪心选 ΔL 最大的问题

有意思的是问题集本身也是数据驱动的：cluster-phones 先把音素按声学相似度自底向上聚成一棵二叉树，在每个内部节点切一刀得到一个"问题"。它自己发现的分组往往恰好对应鼻音、塞音这些语言学分类——不需要人告诉它。

pdf-id 没有语义

叶子编号只是分裂遍历顺序的产物。同一个 pdf-id 在另一棵树里指向完全不同的东西，所以换树之后旧对齐必须用 convert-ali 重映射，直接复用会全错。

14帧几何：那个 166 × 3000 是怎么来的进阶

两个维度来源完全不同：一个是时间轴的采样几何，一个是决策树的规模。

另一个维度：3000

是决策树的叶子数，等于 pdf 数，等于网络输出层维度。不是算出来的，是配方里给的目标值：

steps/nnet3/chain/build_tree.sh --frame-subsampling-factor 3 \
    3500 data/train_sp data/lang_chain exp/tri3a_ali exp/chain/tree

15WFST：五件必须知道的事深入

一句话版

把词典、语法、发音规则、HMM 拓扑这四种完全不同的知识，表示成同一种数学对象，然后用同一套算子拼成一张巨大的静态图。解码就是在图上找最短路径。

G : words → words       语言模型      权重 = −log P(W)
L : phones → words      发音词典      处理同音词、多音字
C : triphones → phones  上下文展开
H : trans-id → triphones  HMM 拓扑    权重 = −log a(转移)

HCLG = min(det(H ∘ det(C ∘ det(L ∘ G))))

① 半环：一套算法，两种语义

WFST 的权重定义在代数结构"半环"上。换个半环，同一套 compose/determinize 算法就切换了含义：

半环运算用途
Tropical(min, +)Viterbi——只关心最优那一条路径
Log(⊕logadd, +)前向算法——对所有路径求和

② 消歧符号：为算法而生，无物理意义

看个例子

词典里有两个词：

你     →  n  i
你好   →  n  i  h  ao

读完 n i 之后，解码器无法确定已经是"你"了，还是"你好"的前半截。同音词更糟：sh i 可能是"是""事""市"。这让 L∘G 不可确定化，搜索效率崩掉。

解法：在词典里给每个歧义读音末尾加一个辅助符号

你     →  n  i  #1
你好   →  n  i  h  ao  #2

确定化之后再用 fstrmsymbols 把 #1 #2 移除

这些符号不对应任何声音，纯粹是为了让算法成立而存在——这是 WFST 工程里最"不自然"但最必要的一环。

③ 输入标签用 transition-id，不用 pdf-id

pdf-id 是多对一的，反推不出音素身份、分不清自环与前进。而对齐、判别训练、词边界时间戳全依赖这些信息。所以 HCLG 的输入标签是 (phone, hmm-state, pdf, 第几条出弧) 组成的 transition-id。

④ weight pushing：对搜索效率影响最大的一步

把权重尽量往图的起点方向推，使每个状态的出弧权重归一化。不改变任何完整路径的总权重，但让 beam 剪枝能更早做出正确判断——否则一条路径可能前半段看起来很差，直到末尾才拿到低权重，早就被剪掉了。

⑤ WeNet 的 TLG：瘦了两层的 HCLG

Kaldi:  H  ∘  C  ∘  L  ∘  G
        ↑     ↑
     HMM拓扑  三音素上下文          ← 端到端时代这两层没了

WeNet:  T  ∘  L  ∘  G
        ↑
    CTC 拓扑（blank 自环 + 重复合并规则）

为什么端到端时代还要 WFST：纯文本永远比音频多。生产环境常有几百 G 的领域语料而音频只有几百小时，n-gram + WFST 是把这些文本用起来的最直接手段。学术上"不够端到端"，线上确实有效。

16自注意力与 Conformer进阶

一句话版

自注意力让每一帧都能"看见"整句里的任意一帧，用来消同音歧义；卷积擅长捕捉相邻几帧的局部细节。Conformer 把两者串起来，成了现代 ASR 的标准编码器。

自注意力在 ASR 里到底解决什么

看个例子

音频："他在食堂吃饭"。

问题：shi tang 这两个音节，声学上和"试探"几乎无法区分。传统方案靠外挂的 n-gram 语言模型在解码时投票。

自注意力的做法：编码 shi 这一帧时，直接去看后面"吃饭"那几帧，给它们高权重。于是 shi 的表征里已经携带了"这是个吃东西的场景"的信息，输出层自然倾向"食"。

语言知识被吸进了声学编码器内部——这就是端到端模型不再那么依赖外挂 LM 的原因。

机制上，每一帧生成三个向量：Query（我要找什么）、Key（我是什么）、Value（我能提供什么）。用当前帧的 Q 和所有帧的 K 做点积得到权重，再对 V 加权求和：

Attention(Q,K,V) = softmax( Q·Kᵀ / √d ) · V

除以 √d 是为了防止点积随维度增大而爆炸，softmax 饱和梯度消失

为什么还需要卷积

自注意力卷积
视野全局，任意两帧直连局部，固定几帧窗口
擅长长距离依赖、语义消歧共振峰过渡、音素内部细节、局部时序模式
计算量O(T²)，长音频吃不消O(T)，线性
位置信息本身没有，要靠位置编码天然携带

Conformer 块：马卡龙结构

输入
 ├─▶ ½ 前馈层 (FFN)           ← 半步残差
 ├─▶ 多头自注意力 (MHSA)      ← 全局上下文
 ├─▶ 卷积模块 (Conv)          ← 局部细节，流式时用因果卷积
 ├─▶ ½ 前馈层 (FFN)           ← 半步残差
 └─▶ LayerNorm
输出

两个半步前馈把注意力和卷积"夹"在中间，形似马卡龙。流式的关键在卷积模块必须是因果的（只看过去），配合注意力掩码限制右侧视野，就得到了 WeNet 的 dynamic chunk 能力。

后续演进：zipformer（icefall）用多尺度下采样结构进一步降算力，是目前端侧 transducer 的主流；E-Branchformer 把注意力和卷积改成并行双分支再融合。

17beam search 与 lattice进阶

一句话版

最优路径搜不起（组合爆炸），所以每一步只留下最好的 N 条候选往下走。这个"只留 N 条"就是 beam；把留下来的候选连同得分一起保存，就是 lattice。

看个例子 · beam = 3 
t=1  候选：  今(-0.2)  金(-1.8)  斤(-2.4)  京(-3.1)  ✂ 剪掉第4条以后
t=2  扩展：  今天(-0.5)  今年(-1.2)  金天(-2.6)  ...  ← 每条候选各扩展一批
     剪枝：  只保留总分最好的 3 条
t=3  ...

两种剪枝同时用：相对阈值（beam=15，比当前最优差 15 以上的直接扔）和绝对数量（max-active，最多保留多少个活跃节点）。前者保证质量，后者保证最坏情况下的耗时可控。

lattice：剪枝的副产品，却是最有价值的中间结果

用一个更宽松的 lattice-beam 保留次优路径，得到一个紧凑的图，里面编码了成百上千条候选句子。每条弧上带着：词、声学得分、图得分（语言模型）、帧级时间边界。

关键价值是把两种得分解耦保存，于是后面可以：

  • LM 重打分——用大 n-gram 或 RNNLM 替换掉图得分重新排序，不需要重新解码
  • MBR 解码——不选最优路径，而是选"期望错误率最小"的那条，通常再降一点 WER
  • 置信度估计——某个词在所有候选里出现的后验概率，用来判断"这个词靠不靠谱"
  • 关键词检索——不用重新识别，直接在 lattice 里搜

CTC 的对应物叫 prefix beam search：因为多条路径会折叠成同一个文本前缀，剪枝时要把它们的概率合并（而不是当成不同候选），这是 CTC 解码实现里最容易写错的地方。

18强制对齐与发音评测深入

一句话版

已经知道音频和它对应的文字，求每个字、每个音素的精确起止时间。这是端到端时代 Kaldi 依然不可替代的场景。

它和识别不是同一件事

识别是在所有可能的句子里搜最优；强制对齐是句子已知，只在唯一一条正确路径上找最优的时间划分。所以解码图不是 HCLG，而是一条把这句话展开成音素序列的线性图（Kaldi 里叫 training graph）：

文本 "你好"
  ↓ 查词典 L
音素 n  i  h  ao
  ↓ 展开成 HMM 状态，每个状态带自环
线性图： [n1]→[n2]→[n3]→[i1]→[i2]→[i3]→[h1]→…
         ↺     ↺     ↺     ↺                    自环允许任意拉长

  ↓ 在这张图上跑 Viterbi（就是 05 节那个手算的规模化版本）
输出： n  [0.00–0.08]   i  [0.08–0.21]   h  [0.21–0.27]   ao [0.27–0.45]

因为路径唯一，搜索空间极小，速度比识别快得多，而且不会出现"识别错了"这种事——只可能是边界划得不准。

为什么端到端做不了这件事

CTC 的峰值对齐

CTC 训练时并不约束"什么时候输出"，模型学到的最省事策略是：在音素中间某一帧突然输出一个尖峰，其余全是 blank。所以 CTC 给的所谓时间戳是尖峰的位置，既不是音素起点也不是终点，还系统性地偏移。Attention 的注意力权重更不可靠——它压根不保证单调。

这就是为什么做发音评测、口型驱动、TTS 数据标注的团队，至今还在用 Kaldi 或基于 Kaldi 的 MFA。

GOP：发音评测的底层公式

所有口语打分 App 的核心都是这一个式子。思路非常直白：把学习者发的这段音，和"标准答案音素"以及"所有其他音素"分别比一比。

              P(o | p)                    o = 这一段音频
GOP(p) = log ─────────────           p = 按课文他应该发的音素
             max_q P(o | q)          q = 遍历所有音素

发音标准 → p 本身就是最像的那个 → 分子分母相等 → GOP ≈ 0
发音跑偏 → 某个 q 比 p 更像       → 分母更大       → GOP 变成很负的数

实现分两步：先做强制对齐拿到每个音素的时间段，再在每段上算 GOP。用 DNN 的话可以直接用后验形式 log[P(p|o) / max_q P(q|o)]，省掉先验换算。

看个例子

中国学生读英文 think，把 /θ/ 发成了 /s/：

目标音素 p = /θ/     该段的 P(o|/θ/) 较低
最像的  q = /s/     该段的 P(o|/s/)  很高

GOP(/θ/) = log(低 / 高) = 一个明显的负数  →  判定该音素发音错误
                                          →  还能告诉他"你发成了 /s/"

这比单纯打个总分有用得多——能指出错在哪个音、错成了什么，这才是评测产品的价值所在。

三个必踩的坑

  • 文本必须和音频严格一致。多一个字少一个字，Viterbi 会把误差扩散到前后一大片。稳妥做法是先跑一遍 ASR，和给定文本比对，差异大的直接丢弃不对齐
  • OOV 词要先生成发音。词典里没有的人名、术语、外来词，需要用 G2P 模型（字形转音素）临时补进词典，否则整句对齐失败
  • 长音频必须分段。Viterbi 的 DP 表是 帧数 × 状态数，一小时音频直接内存爆炸。先用文本里的标点粗切成句子，逐句对齐

20前端信号处理进阶

一句话版

麦克风到 ASR 之间还有一整条信号链。远场场景下，这条链的质量比换模型的影响大一个数量级——但它也最容易被做反。

信号链的顺序不能乱

麦克风阵列
  │
  ├─ AEC 回声消除        ← 必须最先，因为参考信号在这一级才对齐
  ├─ 去混响 Dereverb
  ├─ 波束成形 Beamforming ← 需要多麦克风
  ├─ 降噪 NS
  ├─ AGC 自动增益
  ├─ VAD                 ← 见 21 节
  └─ ASR

顺序错了效果会明显打折。比如先降噪再 AEC，回声已经被非线性处理过，自适应滤波器收敛不了。

模块解决什么方法难点
AEC
回声消除		 设备自己在放音（TTS 回复、音乐），麦克风收进来。不消掉就会自问自答 自适应滤波（NLMS / RLS / 分块频域）+ 非线性残差抑制 扬声器非线性失真、采集与播放的时钟漂移、双讲（双方同时说话）
去混响 房间反射让每个音素拖尾，糊掉相邻音素的边界 WPE（加权预测误差）是事实标准 RT60 > 0.5 s 就明显掉点。比噪声更难对付，因为它和语音完全相关
波束成形 利用声源方向做空间滤波，压制其他方向来的干扰 延迟求和(DAS) → MVDR → GEV；配 SRP-PHAT / GCC-PHAT 做方向估计 需要麦克风阵列；DOA 估计错了会把目标当噪声压掉
降噪 压制稳态和非稳态噪声 谱减 / 维纳滤波 → 神经降噪（RNNoise、DeepFilterNet） 见下面那个大坑
AGC 把音量拉到模型习惯的范围 慢速自动增益 激进的 AGC 会在静音段把底噪放大，直接毒害 VAD
最大的坑：给人听的降噪 ≠ 给机器听的降噪

人耳评价降噪看的是"听着干净、不刺耳"，所以算法会激进地压制残余噪声。但这种压制是非线性的，它在压掉噪声的同时也扭曲了语音的谱结构——而 ASR 模型是在未处理或轻处理的数据上训练的。

结果就是那个经典现象：降噪之后人听着舒服多了，ASR 反而更差了。

两个解法，选一个：① 把前端处理后的数据拿去 fine-tune 声学模型，让训练和推理的前端一致；② 把各种前端处理的效果加进训练数据增广。关键是训练与推理的信号链必须匹配——这是远场系统掉点最常见的隐形原因。

唤醒词（KWS）：端侧的常驻哨兵

端侧不可能一直跑完整 ASR（功耗扛不住），所以要一个极小的模型常开监听，听到唤醒词才叫醒主流程。典型两级架构：

低功耗 DSP 常开  ──▶ 粗检测（宁可错报，不能漏报）
                       │ 触发
                  唤醒主处理器 ──▶ 二次确认（严格判定，滤掉误报）
                                     │ 确认
                                  启动完整 ASR

两个指标：FAR（误唤醒次数 / 小时，用户感知最强的指标）和 FRR（漏唤醒率）。这两者只能权衡，两级架构的意义就是让第一级偏向低 FRR、第二级偏向低 FAR。功耗预算通常在毫瓦级。

远场系统的投入顺序

如果做的是远场场景（会议室、车载、智能音箱），性价比排序是：① 麦克风阵列和声学设计（改硬件，收益最大）→ ② AEC 和去混响 → ③ 前端与模型的一致性 fine-tune → ④ 换更好的 ASR 模型。很多团队从第 ④ 步开始，然后困惑为什么换了 SOTA 模型还是不行。

21VAD 与切分入门

切错句子比认错字更致命。这一节的参数调整，投入产出比高于换模型。

核心观念

VAD 只回答"哪里有语音"，断句是另一件事。把两者绑在一起是多数系统出问题的根源。物理边界交给 VAD（保证不切在字中间），逻辑边界交给标点模型（保证句子完整）。

方案特点
能量 + 过零率信噪比低于 15 dB 基本不可用
WebRTC VADGMM，4 档激进度，微秒级；音乐 / 键盘声误判高
Silero VAD神经网络，约 1–2 MB，TorchScript/ONNX。默认选它
FSMN-VAD（FunASR）中文调优好，直接输出段落边界。中文项目选它
Pyannote segmentation重，但带说话人变更检测，多人场景用

比选哪个 VAD 更重要的六件事

① 双阈值迟滞

进入语音用高阈值（0.6），退出用低阈值（0.35）。单阈值会在边界疯狂抖动，产生大量碎片段。

② 边界外扩 padding

start = max(0,   vad_start − 0.25)   # 前扩 250 ms
end   = min(dur, vad_end   + 0.30)   # 后扩 300 ms

VAD 边界总是偏紧：爆破音 /p/ /t/ /k/ 的闭塞段本身就是静音，词尾浊音尾迹能量也很低。不外扩就会系统性吃掉首尾音素。这是最常见、最容易修的错误。

③ 时长约束

min_silence_duration_ms = 300~500    # 短于此不算断句（正常呼吸停顿）
min_speech_duration_ms  = 100~250    # 短于此丢弃（咂嘴、点击、门响）
speech_pad_ms           = 200~300
max_speech_duration_s   = 20~28      # 强制切分上限

min_silence_duration 最需要按场景调：新闻播报 300 ms 够，自然对话要 500 ms+（否则一句被切成七八段），朗读长文可到 700 ms。

④ 强制切分点要挑，不能直接切

window = audio[(t−2)*sr : t*sr]       # 撞上限前 2 秒的窗口
cut    = argmin(frame_energy(window)) # 找局部最静点，再对齐到过零点

⑤ 重叠切分 + LCS 去重

段A: …今天的会议主要讨论三个议题
段B:        主要讨论三个议题第一是预算…
                    ↓ 最长公共子序列对齐去重
     …今天的会议主要讨论三个议题第一是预算…

段间留 1–2 s 重叠。成本是算力多 10–20%，收益是边界错字基本消失。长音频强烈建议加。

⑥ 两阶段断句

粗切（VAD，只保证不切在字中间，段可以长）
  → ASR 转写 → 标点模型重新断句 → 按句号/问号重组输出

用户看到的句子边界来自标点模型，不来自 VAD。即使 VAD 切得难看，输出仍是完整句子。

22标点恢复与 ITN入门

标点：三条路线

路线做法取舍
A 独立后处理
主流		BERT-like 编码器做 token 分类，逐 token 预测 {O, 逗号, 句号, 问号, 顿号}可单独训练 / 替换 / 领域微调。中文用 FunASR 的 CT-Transformer，它把"等多少右上下文"变成可控参数，避免流式下标点无限延迟
B ASR 直出Whisper、Paraformer-large 带标点版本能用上声学信息（停顿时长、句末语调），理论上限更高；但不可控、不能单独调
C LLM 后处理整段丢给 LLM 加标点分段效果最好，但会改写原意——转写场景慎用，用户要的是忠实转写不是润色

ITN：口语形式 → 书面形式

二零二六年三月五号    →  2026年3月5日
百分之三十点五        →  30.5%
一千二百三十四块钱    →  1234元
下午三点半            →  15:30
幺三八零零一三八零零  →  13800138000

主流手段是 WFST 规则，用 Pynini 编写编译成 OpenFST。实现：NVIDIA nemo_text_processing、WeNet WeTextProcessing。两阶段架构：

classify   "二零二六年三月五号"
           → date { year: "2026" month: "3" day: "5" }
verbalize  → "2026年3月5日"

为什么是 FST 而不是正则

  • 数字有递归组合结构（"一千二百三十四"），正则表达不了
  • 存在歧义（"一二三"是 123 还是 一、二、三？），FST 可加权让解码选最优路径
  • 规则多了性能不退化，可组合、可确定化、可审计
别用 seq2seq 做 ITN

ITN 处理的恰恰是数字——医疗剂量、金额、电话号码，错一位就是事故。小模型会幻觉。确定性在这里是硬需求，不能用概率模型。要更聪明的上下文判断（"三月五号"是日期还是编号）可以加 LLM 二次判断，但 FST 的输出必须是兜底，同时保留原始转写以便回溯。

23热词偏置进阶

按侵入模型的深度分四层，成本与效果同步递增。中文还有一个几乎免费的第五种做法。

1

解码时浅融合（shallow fusion）

beam search 打分时给匹配热词的路径加 bonus，用 Aho-Corasick 自动机跟踪多模式前缀匹配状态。WeNet、sherpa-onnx、icefall 都是这个方案。

零训练秒级生效每用户独立词表>300 条后误触发上升
2

WFST 上下文图

热词编成独立 context FST，与 TLG / HCLG 做 on-the-fly composition。比第 1 层规范（可表达短语、可加权），实现复杂。

3

模型内置偏置（Deep Biasing）

热词列表编码成 embedding，经 cross-attention 注入解码器；训练时用随机采样的热词表做增广，让模型学会"读偏置列表"。代表：CLAS、SeACo-Paraformer、NeMo contextual adapter。

显著优于浅融合对全 OOV 人名尤其好要训练
4

LLM prompt

直接在 prompt 里写"以下音频涉及：…"。Canary-Qwen、Qwen3-ASR 天然支持。效果最好，延迟最高。

浅融合的两个必须做对的细节

① 部分匹配也要给分。热词"卡尔曼滤波"，若只在完整匹配时加分，beam 在识别出"卡"之后就因得分低被剪掉，活不到匹配成功——必须逐 token 递增地给 bonus。
② 匹配失败要全额扣回。否则"卡"开头的所有词被无差别抬高，误触发爆炸。

"卡" +1.0 ─▶ "卡尔" +1.0 ─▶ "卡尔曼" +1.0 ─▶ 匹配成功，保留 +3.0
                         └─▶ "卡尔顿"  fail  ─▶ 退回 −2.0

中文特有：拼音层纠错（务必做）

中文 ASR 错误 80% 以上是同音 / 近音字，纯后处理、几十行代码，对专业术语的召回提升往往比调模型还大。

"张伟提交了报告"  → zhang wei ...
热词 "章炜"        → zhang wei     → 拼音匹配 → 替换
  • pypinyin 转拼音，保留声调但匹配时可忽略（声调错误很常见）
  • 模糊音映射覆盖南方口音：zh/z ch/c sh/s n/l en/eng in/ing
  • 编辑距离阈值 + 最小长度限制（2 字以下不替换，误伤太多）
  • 只在原文置信度低的位置替换，高置信度处不动

推荐组合：浅融合（词表 < 300）+ 拼音模糊纠错覆盖长尾 +（可选）领域数据 fine-tune。

24幻觉与循环重复进阶

Whisper 这类 AED 模型特有的病。根源在第 09 节说过：attention decoder 没有单调对齐约束。

  1. 结构上允许——decoder 理论上可以完全无视音频自己生成。CTC / transducer 每输出一个 token 必须前进音频帧，做不到这件事。
  2. 训练数据教会的——68 万小时弱标注里大量字幕，学会了"听不清就补一句常见的"：感谢观看、请不吝点赞订阅、字幕由XXX提供、Thanks for watching。
  3. 级联放大——30 s 窗口，前一窗口输出作为下一窗口 prompt，错了一路传播。

触发条件高度集中在静音段、纯噪声段、音乐段、极低信噪比段。这解释了为什么第 1 条手段效果压倒性。

25中文特有的坑入门

大部分 ASR 教程是英文本位的。中文有五个绕不过去的差异，每个都对应工程上的具体动作。

① 声调：中文和英文配方最大的特征差异

中文是声调语言，声调直接承载词义：mā 妈 / má 麻 / mǎ 马 / mà 骂。而基频（F0）恰恰是倒谱变换刻意丢掉的那部分（见 12 节）——为了去掉说话人差异，把激励信息一起扔了。

Kaldi 中文配方的对策：额外拼 3 维 pitch 特征
  steps/make_mfcc_pitch.sh

  维度 1：POV（probability of voicing，浊音概率）
  维度 2：归一化的 log-pitch
  维度 3：delta-pitch

端到端模型直接吃 fbank，理论上能从谐波结构隐式学到基频轨迹，但显式拼 pitch 通常仍有收益，尤其在低资源和方言场景。这是中文项目值得单独试一下的开关。

② 多音字：强制对齐的主要误差源

字读音例
行xíng / háng行走 / 银行
长cháng / zhǎng长度 / 长大
了le / liǎo吃了 / 了解
重zhòng / chóng重量 / 重复

在词典里一个词条对应多条发音，L.fst 因此有多条并行路径，需要消歧符号（见 15 节 ②）。识别时问题不大（端到端直接输出汉字，根本不经过读音）；但强制对齐和 TTS 会被它坑惨——对齐时选错读音，那一段的音素边界全废。

③ 中英混读（code-switching）

"打开 PPT"、"发个 email 给我"、"5G 网络"、"做个 review"。日常口语里极其常见，但训练数据里占比极低。

  • 建模单元：主流做法是中文用字、英文用 BPE 的混合词表。WeNet、Paraformer 都是这样
  • 数据是真瓶颈：公开中文语料里混读样本稀少。缓解手段是用 TTS 合成混读句做增广
  • 缩略语更糟："CPU"、"API"、"FOC" 这类逐字母读的，声学上和普通英文单词完全不同，基本必须靠热词兜底

④ 分词：为什么中文按字算 CER

中文没有天然词边界，"研究生命起源"可以切成"研究/生命/起源"也可以是"研究生/命/起源"。所以：

  • 评测按字算 CER，绕开分词的歧义
  • 但如果用词级 n-gram 语言模型，训练语料就必须先分词，分词器的错误会传导进 LM
  • 现代方案直接字级建模，把分词这件事彻底绕开

⑤ 口音与繁简

普通话口音的三大变异，正好解释了第 23 节那张模糊音映射表的由来：

平翘舌不分   z/zh   c/ch   s/sh      ← 南方普遍
前后鼻音不分  en/eng  in/ing  an/ang   ← 极普遍
n / l 不分                             ← 西南官话

另外训练数据混杂简繁体会导致输出不一致，后处理统一即可（OpenCC）。方言场景目前 Qwen3-ASR 覆盖 22 种，是唯一实用选项。

26说话人分离进阶

一句话版

回答"谁在什么时候说话"。和 ASR 是正交的两件事，但会议纪要、访谈转写、客服质检都必须有。

两条路线

A

级联式（目前主流）

VAD → 切成小段 → 每段提取说话人嵌入 → 聚类 → 分配标签

VAD ─▶ 切分 ─▶ x-vector / ECAPA-TDNN ─▶ 谱聚类 / AHC ─▶ 标签
pyannote.audioWeSpeaker3D-Speaker

优点：模块化、可控、说话人数可以事先未知。缺点：处理不了重叠语音——两个人同时说话时，一段音频只能给一个标签。

B

端到端 EEND

直接输出"每一帧、每个说话人是否在说话"的多标签矩阵，天然支持重叠。缺点是说话人数通常要预设上限，长音频难处理。

说话人嵌入是什么

一个把任意长度语音映射成固定维度向量（典型 192 或 256 维）的网络，训练目标是同一个人的不同录音靠得近，不同人的离得远。x-vector 是 TDNN 时代的经典，ECAPA-TDNN 是目前的强基线。同一套嵌入既能做分离（聚类），也能做声纹验证（算余弦相似度）。

和 ASR 怎么拼

方案做法评价
A 先分离再识别每个说话人段落单独送 ASR简单，但分离的切分不理想会直接伤害 ASR 精度
B 先识别再对齐用 ASR 的词级时间戳去查分离结果，给每个词打标签主流做法。FunASR、WhisperX 都是这个方案
C 联合建模一个模型同时输出内容和说话人研究阶段

指标是 DER（Diarization Error Rate）= (漏检 + 虚警 + 说话人混淆) / 总语音时长。

三个实战坑

① 说话人数未知时聚类阈值极敏感。能提前告诉它人数就一定要告诉。
② 短发言几乎必错。"嗯""对""好的"这种 0.3 秒的应答，嵌入提取不到足够信息，通常被归到上一个说话人。
③ 电话/双声道录音别用 diarization。如果每个人本来就在独立声道上，直接按声道分，准确率 100%，还省一套模型。这个错误比想象中常见。

27端侧部署与延迟预算进阶

一句话版

端侧的约束是内存和算力，主要手段是量化；实时系统的约束是延迟，而延迟的大头往往不是计算，是 chunk 累积。

量化：拿精度换体积和速度

格式体积精度损失说明
FP321×基线训练格式
FP16 / BF160.5×几乎无GPU 部署首选
INT8 动态量化0.25×CER 相对 +1~3%权重定标，激活运行时量化。ONNX Runtime / sherpa-onnx 的默认路径，不需要校准集
INT8 静态量化0.25×+1~2%激活也预先定标，需要几百条校准音频
QAT0.25×< 1%训练时就模拟量化舍入，效果最好但要重训

GGML Q4_0~0.15×有感，长音频更明显内存实在紧张才用
量化的隐藏瓶颈

模型量化到 int8 之后，特征提取常常反而成为瓶颈——FFT、Mel 滤波、log 还是浮点在跑。在没有 FPU 或 FPU 很弱的芯片上，fbank 的耗时可能超过网络前向。做极限优化时这一段也要定点化。

延迟预算：拆开看大头在哪

实时系统被投诉"反应慢"时，先做这个分解，别一上来就去优化模型：

端到端首字延迟 = 音频缓冲 + VAD 判定 + chunk 累积 + 右上下文 + 计算 + 后处理 + 网络往返

典型流式配置（chunk = 16 个输出帧 @ 40 ms）:

  音频采集缓冲          20 ~ 60 ms
  VAD 起点判定          30 ~ 100 ms
  chunk 累积           640 ms      ◀── 大头在这里
  右上下文 lookahead   160 ~ 320 ms
  网络前向计算          50 ~ 150 ms
  标点等待              0 ~ 500 ms  ◀── CT-Transformer 可控
  网络往返（云端）      30 ~ 200 ms
  ──────────────────────────────
  合计                 约 0.9 ~ 2.0 s

结论很清楚：计算通常只占 10% 不到。想降延迟，第一刀砍 chunk（精度换延迟），第二刀限制右上下文，第三刀把标点切到低延迟模式。换个更快的模型往往只省下几十毫秒，白忙。

硬件对应关系

硬件可行方案
MCU（Cortex-M 级）连续 ASR 很勉强。现实做法是只做关键词唤醒，唤醒后把音频上传

四个必做的工程细节

  • 模型和解码图预加载。首次推理的冷启动（内存分配、图编译）可能是稳态的 10 倍，服务起来先跑一次空推理预热
  • 音频用环形缓冲，避免每个 chunk 都做一次内存拷贝
  • 限制推理线程数。ONNX Runtime 默认会开满核心，在大小核架构上被调度到小核反而更慢，且抢占其他任务
  • 流式状态要能重置。一段说完必须清掉 encoder 的 cache 和 decoder 的历史，否则上一句会污染下一句——这是流式实现最常见的 bug
选型时容易忽略的一条

端侧看的不是模型文件大小，是运行时峰值内存。它 ≈ 权重 + 激活缓存 + 解码图/词表 + 音频缓冲。带 WFST 解码图的方案，图本身可能比模型还大（几百 MB），这在嵌入式上往往才是真正的门槛——所以端侧一般不挂 WFST，用 transducer 直接出字。

28数据与评测进阶

一句话版

模型选型只决定起点，数据和评测决定你能走多远。而绝大多数项目死在"线下涨了线上不涨"——那是评测方法的问题，不是模型的问题。

目标数据量说明
只加热词 / 领域 n-gram0 h只要纯文本。先试这个，很多"识别不准"到这一步就解决了

  • 公开集——中文：AISHELL 系列、WenetSpeech（万小时级）；英文：LibriSpeech、GigaSpeech、Common Voice。先用公开集验证流程跑得通，再谈自采
  • 伪标注——用最强的大模型去转写你手上的无标注音频，只保留高置信度的部分当训练数据。这是目前性价比最高的扩量手段
  • TTS 合成——专门用来补长尾：中英混读、专业术语、数字读法。合成数据不能当主食，但补特定短板很有效
  • 自采——最贵，但如果你的场景（远场、特定设备、特定口音）和所有公开集都不像，这一步省不掉

① 用一个强 ASR 跑一遍，和标注比 CER，超过阈值的丢
   （分不清是标注错还是音频烂，但都不该留）
② 强制对齐失败或对齐得分过低的丢       ← 见 18 节

评测：项目成败的真正分水岭

一个总 CER 数字没有任何指导意义

它把所有场景平均掉了。真实情况往往是：安静近场 3%、嘈杂远场 25%，平均下来 8% 看着还行，但用户在嘈杂环境里就是用不了。测试集必须分场景切开看。

测试集怎么建

  • 按维度分桶：安静/嘈杂、近场/远场、口音、领域、句长。每桶至少几百条，单独报 CER
  • 说话人级别隔离。训练集和测试集不能有同一个说话人——只做句子级去重是不够的，模型会记住音色
  • 冻结。测试集一旦定下就不再改，否则每次调参都在污染它
  • 建"困难集"。把线上出错的 case 持续收集起来，做成回归测试集。这是最有价值的一份数据资产，比任何公开集都值钱

线下涨了线上不涨，通常是这三个原因

  1. 分布不一致——测试集是朗读的，线上是自然对话；测试集是手机录的，线上是会议室吊麦
  2. 间接污染——测试集里的说话人、录音环境、甚至文本出现在训练集里
  3. 只看平均没看长尾——平均 CER 降了 1 个点，但最差的那 5% 场景反而变差了，而用户的抱怨全来自那 5%

A/B 要看的不只是 CER

指标为什么重要
分场景 CER基础，但只是起点
延迟 P99平均延迟没意义，用户记住的是最慢的那几次
拒识率 / 空输出率识别成空白比识别错更伤体验
用户重说率最诚实的指标。用户重复说一遍，说明上一次没被正确理解——它把 ASR、VAD、下游理解的问题全都捕获了
关键实体准确率人名、数字、订单号错一个字就是事故，这类词单独算准确率
成本的量级感

训练：千小时级数据训一个 Conformer，多卡 GPU 数天量级；fine-tune 通常是单卡数小时到一两天。
推理：云 API 按时长计费，自建要摊 GPU 成本。盈亏平衡点大致在每天几百小时音频的量级——低于这个量用 API 更划算，高于这个量自建开始有优势。
端侧：一次性开发成本高（适配、量化、调优），但边际成本为零，且没有隐私和网络问题。
这些都是量级参考，实际差异可以很大，务必按自己的场景实测。

1

排除环境、编码、采样率这些低级问题。这一步失败就不用往下查了。

2

关掉所有后处理，看裸 ASR 输出

定位是模型问题还是后处理问题。很多"模型不准"其实是标点模型或 ITN 改坏的。

3

把 VAD 切出来的段落 dump 成 wav，逐段听

90% 的"模型不准"其实是切分问题。这一步几乎每次都有收获，但几乎没人做。

4

看 n-best / lattice

如果正确答案在 n-best 里但排不到第一 → 是语言模型或打分权重问题，不是声学问题，别去 fine-tune 声学模型。

5

算 oracle WER

n-best 里最好那条的 WER。它是重打分、rescoring、LLM 纠错能达到的天花板。如果 oracle WER 已经接近实际 WER，说明正确答案根本没进候选，再怎么重打分都没用——该换声学模型或调 beam 了。

最容易被忽略的三个低级错误

① 采样率不匹配。用 8 kHz 电话音频喂 16 kHz 模型，或者用 44.1 kHz 直接送进去，都会得到一堆胡言乱语而不报错。
② 声道搞错。立体声直接当单声道读，左右声道交错解释成时域序列。
③ 特征配置不一致。训练用 fbank80、推理用 MFCC40，模型不会报错，只会输出垃圾。

31当前的真正难点入门

开源模型榜单前十的差距不到 1 个百分点——这不说明 ASR 解决了，只说明这个测试集测不动了。真实的缺口在下面这些地方。

① 远场与重叠语音：最大的一道坎

这是目前 ASR 距离"可用"最远的场景。CHiME-7/8 DASR 挑战赛的评测给出了很具体的量级：

场景最好系统 tcpWER特点
CHiME-6（家庭聚会）~20%远场、自然对话、高重叠
Mixer 6（异构设备）~11%设备种类多
NOTSOFAR-1（会议）~11%会议室多麦阵列

对比一下：近场朗读语音的 WER 已经在 2–5%。同样的技术，换到真实的多人对话场景，错误率翻了 4–10 倍。

难点拆开是三层：重叠语音（各场景重叠比例在 13.9%–31.7% 之间，两个人同时说话时几乎没有好办法）、说话人计数（第一遍分离数错了人数，后面全盘皆错，而真实场景是 2–8 人不定）、域泛化（在一个场景调好的系统换个房间就退化）。

一个耐人寻味的事实

尽管神经方法层出不穷，CHiME 参赛队伍至今仍然普遍依赖 GSS（Guided Source Separation）这种偏传统的引导式分离方法作为主力。当前的最强流水线大致是：通道选择 → GSS 目标说话人提取 → 基于 WavLM 预训练特征的端到端 ASR → 目标说话人分离做后处理精修。这说明纯端到端在这个问题上还没有真正胜出。

② 幻觉与"不知道自己不知道"

生成式 ASR 越流畅越危险：它产出的错误是通顺的、可信的、和上下文自洽的，比传统系统那种明显的乱码难发现得多。更根本的问题是缺乏可靠的置信度——模型无法告诉你"这一段我没听清"。在医疗、法律、金融场景，一个自信的错误比一个明显的空白危险得多。

③ 流式与精度的根本矛盾

这不是工程问题，是信息论问题：右上下文里的信息，你不等就是拿不到。dynamic chunk、两遍解码这些都是在权衡曲线上移动，没有消除权衡本身。目前 640 ms 延迟对应的精度损失仍然是实打实的。

④ 长音频的上下文一致性

模型窗口有限（Whisper 是 30 s），跨段落的指代、术语一致性、说话人一致性都维持不住。同一个人名在一小时的会议里被写成三种写法，是当前系统的常态。

⑤ 长尾永远训不完

新产品名、新人名、新术语每天都在产生。热词偏置（23 节）是打补丁，不是解决方案——它的容量有上限，且和误触发是此消彼长的。

⑥ 低资源与方言

世界上约 7000 种语言，有可用 ASR 的不到 2%。Meta 的 Omnilingual ASR 把覆盖推到 1600+ 种，但绝大多数语种的质量只能算"能用"。中文的方言同理——22 种方言的覆盖已是目前最好，但和普通话的差距仍然巨大。

⑦ 精度与成本的剪刀差

榜单头部全是 2–3 B 参数的 LLM-ASR。精度最高的模型，恰恰是端侧跑不动、大规模批量转写成本最高的模型。Parakeet 那个 0.6 B / RTFx 3333 的存在说明这条曲线还有很大优化空间，但目前"最准"和"能用"之间是割裂的。

⑧ 评测本身已经失效

公开榜单的干净朗读数据已经饱和，它不再能区分模型的优劣，也不能预测真实场景表现。这反过来伤害了研究——大家在一个测不动的指标上继续优化。这也是为什么 28 节强调你必须建自己的分场景测试集。

32研究方向进阶

这些方向的共同点：它们都在试图跨过"转写"这件事本身。

① 离散语音 token：让语音和文本共用一套 Transformer

目前最热的方向。核心问题是：LLM 吃的是离散 token，而语音是连续、无边界的。把语音量化成离散单元，语音就能和文字在同一个模型里共存。

类型来源保留什么代表
声学 token神经编解码器，目标是重建信号音色、韵律、细节都在，但冗余SoundStream、EnCodec、DAC（用残差量化 RVQ）
语义 token自监督模型加量化音素和语义内容，丢掉韵律和音色wav2vec 2.0、HuBERT、WavLM

公开的难点也很明确：码本坍缩（VQ 只有一部分码字被用到，或使用极不均衡）、重建与表示的矛盾（为重建优化的 token 对下游任务太冗余，为语义优化的又丢了韵律）、序列长度问题（token 帧率 25–100 Hz，远长于音素序列，让 decoder-only 模型训练和推理都不稳）、以及说话人相关任务上明显弱于连续特征。

② 全双工语音对话

从"轮流说话"走向"同步对话"：系统要能边听边说、被打断时立刻停、在你说话的间隙插入"嗯"。这需要模型同时具备持续的听和持续的说两条流，而不是 ASR → LLM → TTS 的串行流水线。

这个方向正在快速形成体系，已经出现了专门的全双工评测基准（如 τ-Voice 这类面向真实域的语音 agent benchmark），以及把语音、语言、动作同步建模的工作。对做交互产品的人，这是未来两三年最值得盯的方向——因为它改变的不是精度，是交互形态。

③ 目标说话人提取与"分离-识别"联合建模

针对第 31 节的头号难题。思路是用声纹作为条件，从混合语音里直接抽出目标说话人，而不是先分离再识别。CHiME-9 已经出现了专门的多通道对话识别赛道（MCoRec）。把内容识别和说话人归属放进一个模型里联合优化，是取代当前"ASR + diarization 拼接"方案的方向。

④ 可微 FST：结构先验的回归

有意思的一条线：k2 把 FSA/FST 的组合和前向后向实现成 GPU 上可微的算子，于是 WFST 那套结构化解码可以直接嵌进端到端模型的训练里。

这背后是一个认识上的回摆——把结构先验全扔掉未必是对的，只是过去它被硬编码在流水线里、无法和网络联合优化。现在它可以了。CTC/RNN-T 的训练目标本质上就是"对所有对齐路径求和"，而那正是 log 半环上的前向算法（15 节）。

⑤ 大规模多语种自监督

XLS-R、MMS、Omnilingual ASR 这条线，用自监督把表征学在几千种语言的无标注音频上，再用极少量标注做微调。这是低资源语种唯一现实的路径。

⑥ 高效架构

针对第 31 节的成本剪刀差。zipformer 的多尺度下采样、线性注意力、状态空间模型（Mamba 系）在语音上的应用，目标都是把 O(T²) 的注意力换掉，让长音频和端侧都跑得动。

⑦ 不确定性量化

让模型知道自己不确定——这是幻觉问题的根本解而不是补丁。一个能可靠输出"这 3 秒我没听清"的模型，在医疗和法律场景的价值远高于平均 CER 再低 1 个点。目前这块的进展慢于其他方向，但需求最刚性。

一个判断

把这七个方向连起来看，主线是很清楚的：ASR 正在从一个独立的"转写模块"，变成语音大模型里的一种能力。未来的系统大概率不再有"ASR 组件"这个东西——转写、翻译、分离、理解、回应会在同一个模型里发生。但这条路上有两个东西大概率会留下来：需要精确时间的场景仍然要专门的对齐工具（18 节），端侧和实时场景仍然要小而专的模型（27 节）。

D. 决策树：似然增益的推导

为什么节点似然是那个式子？把最大似然解 μ̂ = m/γ、σ̂² = v/γ − μ̂² 代回去：

D1 推导
L(S) = Σ_t γ_t·log N(x_t; μ̂, σ̂²)

     = −½ Σ_t γ_t [ d·log2π + Σ_i log σ̂_i² + Σ_i (x_ti − μ̂_i)²/σ̂_i² ]
                                              └────── 关键项 ──────┘

关键项：Σ_t γ_t Σ_i (x_ti−μ̂_i)²/σ̂_i² = Σ_i (1/σ̂_i²)·(γ·σ̂_i²) = γ·d
        ↑ 因为 σ̂² 就是加权方差，代回去分子分母抵消，与数据无关！

∴  L(S) = −½·γ(S)·[ d·log2π + Σ_i log σ̂_i²(S) + d ]

这个抵消是整件事能跑起来的原因：似然只取决于占用计数和方差，不需要重新遍历数据。于是建树时只要维护三个充分统计量 γ, m=Σγx, v=Σγx²，就能对任意子集瞬间算出似然——几百万个候选分裂才评估得起。

停止条件： ΔL < 阈值   或   γ(叶子) < 最小占用

H2 格子前向
α(t,u) = α(t−1,u)·P(∅ | t−1,u)  +  α(t,u−1)·P(y_u | t,u−1)
         └ 向右：消耗一帧 ┘        └ 向上：输出一个字，不消耗帧 ┘

P(y|X) = α(T,U)·P(∅ | T,U)

和 CTC 的关键差别：P(k|t,u) 的条件里有 u——每一步都能看到已经输出的文字，条件独立假设被打破了。代价是要在整个 T×U 网格上做前向后向，显存占用远高于 CTC 的 T×2L。

当前帧的 Query q = [1, 0, 1, 0]，三个候选帧的 Key：

k₂ = [0, 1.0, 0, 1.0]     与 q 正交
k₃ = [0.9, 0.1, 0.8, 0.2] 与 q 相近

N. 量化

N1 int8 对称量化
s = max|x| / 127                          定标因子

q = clip( round(x / s), −127, 127 )        量化

N2 量化噪声
误差上界：  |x − x̂| ≤ s/2

噪声功率：  E[(x−x̂)²] = s²/12          均匀量化噪声的标准结果

信噪比每增加 1 bit 提升约 6.02 dB
算例 7 · 一组权重量化到 int8 
原始权重： −0.83   0.12   0.47   −0.05   0.91

s = max|x| / 127 = 0.91 / 127 = 0.007165

q  =  −116     17     66      −7     127     ← 存成 int8，体积降到 1/4
x̂  = −0.83118  0.12181  0.47291  −0.05016  0.91000

最大误差 = 0.002913     理论上界 s/2 = 0.003583  ✓
噪声功率 s²/12 = 4.28×10⁻⁶

注意最大的那个权重 0.91 被无损还原（它定义了 scale），误差集中在小权重上。这解释了两件事：① 为什么离群值（outlier）对量化伤害极大——一个异常大的权重会把 scale 拉大，所有其他权重的误差同步放大；② 为什么 per-channel 量化比 per-tensor 好——每个通道独立定标，避免被全局离群值绑架。
